# System services: lifecycle, System settings, defaults/reset, idle discipline, recovery, jobs, OTA, online

## Lifecycle / power (§20)
Sleep, Restart and Power Off use ONE central lifecycle/power path for every caller (Power Menu, Quick Menu, Home, idle timeout, future clients). It owns orchestration (game save-state/pre-power hooks, RGB/display handling, RTC wake where applicable, final action); the UI only requests.
- §20.1 Automatic save state of an active game before Sleep/Restart/Power Off lives in that central flow, never in UI callers.
- §20.2 Restart/Power Off confirmation: keep the clean centered action visual and show `Press again to confirm` laterally, not under the title.
- §20.3 A Sleep → START/POWER input leak into Settings was fixed/qualified: regressions in wake input suppression/routing are blockers.

## System Settings (§21)
- Performance Profile: Auto / Performance / Battery Saver; automatic Battery Saver uses a device-global battery threshold.
- Sleep After / Power Off After: value or Off; sleep-before-poweroff and RTC wake semantics follow qualified hardware capability.
- Storage: SD1/SD2 overview, guided migration/backup between supported storage; never SYSTEM/STATE.
- System Information: reliable live battery/charging, CPU/GPU clock, temperatures, uptime, RAM used/total/free, build, device, network, storage; event-driven where possible, low-frequency sampling only where hardware requires it.
- No generic "Updates & Recovery" category just because it is conventional. Restore Defaults / Reset System Settings with strong confirmation; it never erases ROMs, BIOS, saves or USERDATA and resets controller mapping to the approved default. Before the infrastructure freeze audit all defaults: initial/default/runtime/reset values must agree; no legacy divergent defaults.

## Defaults and Reset System Settings (§37.6)
- Every setting default lives once, in its owning service: `systemd.c` (`DEFAULT_*`: profile Auto, Auto Battery Saver ≤20%, Screensaver Off, Sleep After 10 min, Power Off Off, backup WEEKLY), `audiod.c` (`DEFAULT_*`: output Auto, speaker 70, headphones 50, Bluetooth 50, System Sounds 60, Home Music 60, Applications 100, both cue toggles On), `displayctl.c` (`DEFAULT_BRIGHTNESS` 60), `controllersd.c` (`mapping_defaults`, deadzones 20), `/etc/nuubos/input-bindings.conf`. `S03nuubos-state`/`provision-state.sh` must not write these keys.
- `RESET SYSTEM SETTINGS` (systemd) resets its own config, then calls each owner: `nuubos-audioctl reset-defaults`, `nuubos-displayctl reset`, `nuubos-inputctl bind reset`, D-Bus `org.nuubOS.Controllers1.ResetMappings` (removes `/state/users/*/controllers/*.conf` for ALL users; player assignments kept), `nuubos-storagectl backup-policy WEEKLY`. Replies `ERR reset incomplete` if any step fails (details in `/run/nuubos/systemd.log`). Not reset: users/login mode, per-user language/rumble/RGB, Wi-Fi/Bluetooth pairings, timezone/time/keyboard, storage mode, USERDATA.
## Idle wakeup discipline (§37.9)
- Services must sleep with no timeout when idle; timers are armed only while work is pending (deadline computed, not a fixed tick). Measured 2026-10-05: lightingd/audiod/wifid/bluetoothd/statusd went from ~20 to ~0 wakeups/s.
- Measure on target via `voluntary_ctxt_switches` in `/proc/<pid>/status` over 30 s.
- libdbus `dbus_connection_read_write(conn, ms)` restarts its poll on EINTR: a signal does not wake it. Use own `poll()` on the D-Bus fd + a self-pipe written by the signal handler, then `read_write(conn, 0)`, pop messages, `dbus_connection_flush()` (wifid/bluetoothd pattern). Use `SA_RESTART` and handle `SIGCHLD` the same way instead of periodic `waitpid` (audiod).
- glibc `time()` reads the coarse clock and lags the timerfd by a tick; use `clock_gettime(CLOCK_REALTIME)` for wall-clock display. statusd's minute tick is a `CLOCK_REALTIME` absolute timerfd with `TFD_TIMER_CANCEL_ON_SET`; zone changes come from an inotify watch on `/etc/localtime` + `tzset()`.
- System service supports only `auto`/`battery-saver` (no Performance profile).
- Unsupported rumble/RGB rows are shown as "Unavailable" instead of hidden.
## Recovery, safe mode, diagnostics (§37.16, EPIC-049/050/052)
- Package `nuubos-recovery` (shell only): `/usr/bin/nuubos-diag`, `/usr/sbin/nuubos-recoveryctl`, `/usr/bin/nuubos-ui-supervisor`. Host tests: `sh package/nuubos/nuubos-recovery/tests/{diag-redaction,recovery}.sh` (fake root through `NUUBOS_ROOT`). Target BusyBox has no `timeout` applet (`nuubos-diag` uses its own `bounded`).
- Support bundle: `nuubos-diag bundle [DIR]` → `/userdata/diagnostics/nuubos-support-<UTC>.tar.gz` (last 5 kept, staged then moved, mode 600): `summary.txt` (identity/build/board/kernel, memory, storage, power, thermal, modules, input, network, Wi-Fi saved SSIDs, Bluetooth, service pids, `nuubos-*ctl status`, nuubos.conf, user count, recovery history), `logs/` (`/run/nuubos/*.log` last 500 lines, dmesg, `/boot/nuubos-debug`). Every text goes through `redact` (psk/password/secret/token/key/pin/auth/cookie values, Authorization headers, private keys, 64-hex). Never collected: ROMs, BIOS, saves, `/state/ssh`, `/state/users/*/secrets`.
- Reset scopes (`nuubos-recoveryctl`): `reset-user ID` (STATE prefs: controllers, localization, lighting, input-feedback, settings.conf; USERDATA `appdata/`; saves/states/screenshots/library/music kept; `OK restart-required` for the active user), `reset-system` (= `nuubos-systemctl reset-system-settings`), `repair` (dedups nuubos.conf keys keeping the last, adds missing keys, removes stale `*.tmp*`/`.new.*`, quarantines damaged profiles in `/state/recovery/quarantine`, recreates settings.conf/secrets), `factory-reset settings|userdata` (only schedules `/state/recovery/pending-reset`, replies `OK reboot-required`). Applied at boot: S03 `apply-pending state` (wipes STATE except `ssh/` host keys, `recovery/`, `lost+found`; userdata scope leaves `pending-userdata`), S04 `apply-pending userdata` after the USERDATA mount (removes `users cache retroarch library diagnostics steamlink`). ROMs and BIOS are never touched by any scope. History: `/state/recovery/history.log` (bounded).
- Supervisor: `nuubui-home-session` execs `nuubos-ui-supervisor` (restarts nuubUI; 3 crashes in 120 s → `/state/recovery/safe-mode` + `NUUBOS_SAFE_MODE=1`; 3 more in safe mode → `/run/nuubos/ui-failed`, stop, tty1 stays). Exit 0/143/130 or labwc gone = orderly stop, not a crash. `nuubos-ui-stop` kills the supervisor first.
- UI: Settings → System rows 8 Diagnostics (settings-view 27) and 9 Recovery (28: Repair, Reset User Profile, Factory Reset, Factory Reset and Erase User Data, Exit Safe Mode only in safe mode). Destructive rows: press to arm (prompt in the detail line), press again; erase needs one more press. Resets/factory reset/exit safe mode restart through `ACTION RESTART` (central lifecycle). Safe mode opens Settings directly on view 28. Headless scenes `diagnostics`, `recovery`, `recovery_safe`.
- Not hardware-qualified yet (target was offline on 2026-10-07): bundle on target, factory reset both scopes (boot into OOB, SSH host key kept), supervisor crash loop (`kill -SEGV` nuubUI three times) and safe-mode exit.
## Background jobs (§37.17, EPIC-007)
- Package `nuubos-jobs`: `nuubos-jobd` (`S39nuubos-jobd`, socket `/run/nuubos/jobd.sock` 0600, log `/run/nuubos/jobd.log`) + `nuubos-jobctl status|watch|submit TYPE [ARG]|run TYPE [ARG]|cancel ID|retry ID` (`run` waits and prints the `@result`). Host test: `python3 package/nuubos/nuubos-jobs/tests/jobd.py`.
- Job types are registered by the owning package in `/usr/share/nuubos/jobs/<type>.job` (`COMMAND=` absolute program + fixed args, `SCOPE=device|user`, `CANCEL=`, `RETRY=`, `ARGS=0..4`, `NOTIFY=`). Clients only pass validated plain args (no leading `-`, no control chars). Current types: `support-bundle` (nuubos-recovery), `scrape-game`, `scrape-bulk` (nuubos-scraper).
- Workers: nice 10 + idle I/O priority, `NUUBOS_JOB_ID`/`NUUBOS_JOB_USER` env, report `@progress <0..100|-1> [step]`, `@result <text>`, `@error <reason>` on stdout; exit 0 = succeeded; SIGTERM (process group) = cancel, the worker removes partial output. Max 2 running, one per type, FIFO; same type+args pending = same job id. No automatic retry; finished jobs kept in memory (16) for result/retry; nothing persists.
- Every job = Live Notification `id=job.<n> event=job type= state=queued|running|succeeded|failed|cancelled progress= step= reason=` rendered by the Quick Menu (`toast_view` "job").
## OTA updates and product identity (§37.22, EPIC-048)
- `post-build.sh` writes `/etc/os-release` (NAME=nuubOS, VERSION_ID from `VERSION`, BUILD_ID = `git describe`) with `/usr/lib/os-release` linking to it, and `/usr/share/nuubos/build-id`.
- Package `nuubos-update`: `nuubos-updatectl status|check|download|verify` (libcurl + libsodium): `<UPDATE_URL>/nuubos-update.manifest(.sig)` (key=value: format, version, build, payload, size, sha256, notes) signed Ed25519; public key compiled from `board/nuubos/common/ota/update-key.pub` (64 hex; absent → "unavailable"); resumable payload download (explicit Range; a 200 answer restarts), SHA-256 verified, `.part` deleted when wrong; files in `/userdata/.nuubos-update`. Job type `update-download`.
- `nuubos-update-apply install|apply|boot|confirm|rollback|status`: install marks pending; the pre-power hook `90-update` (restart/poweroff, never sleep) saves the files it will replace into `rollback.tar` (tar keeps modes/links on exFAT), records added files, extracts the payload's files (not dev/proc/sys/run/tmp/state/userdata/media/mnt/var/{run,log,tmp}); S04 `boot` counts unconfirmed boots, the 3rd rolls back and reboots; Home confirms once nuubUI is ready (not in safe mode). A kernel that cannot boot is NOT recoverable yet (needs U-Boot bootcount / A/B): OTA is not production-ready.
- Releases: `tools/ota/make-update.sh KEY.pem OUTDIR [NOTES]` from `output/h700/images/rootfs.tar` (`BR2_TARGET_ROOTFS_TAR=y` now in the defconfig) — key creation instructions in the script. No release key exists yet (user decision; never commit the private key). Host test `sh package/nuubos/nuubos-update/tests/update.sh` (local HTTP server, OpenSSL-signed manifest, fake root).
- UI: Settings → System row 11 Software Update (settings-view 63).
## Online services and offline behaviour (§37.23, EPIC-054/055)
- Settings → System row 12 Online Services (settings-view 64): ScreenScraper, RetroAchievements, Software Update, Remote Services (each opens its page), network shares count. `docs/privacy.md` documents every network-facing feature. Every online call is user-initiated with timeouts (scraper 30 s, RA login 15 s, update connect 15 s / stall 60 s, share mount 15 s); nothing runs automatically except NTP when Automatic Time is on.
