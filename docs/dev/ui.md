# UI: visual grammar, Settings, rendering, localization, themes

Cross-cutting rules (responsive, controller-first, no idle redraw, marquee, localization): CLAUDE.md.

## Visual direction (§11)
Reference: the nuubOS "Small System. Big Adventures." mockup: dark/matte console UI, hero artwork on Home, minimal top bar, Recently Played with cover art and blue focus glow, selected-game metadata, Systems & Collections, Applications, controller hints at the bottom, clean console presentation. Not a fixed-resolution screenshot to scale. Keep the nuubOS blue accent. The RG40XX-V splash is designed/qualified for native 640×480: no oversized typography. Marquee covers Home, Settings, dropdowns, User Picker, Quick Menu, OSD, notifications and future screens.

## Material 3 (user request 2026-10-08)
The UI follows Material Design 3 on the nuubOS dark/matte look with the blue accent (§11 stays the reference). Colour roles (`primary`, `primary-container`, `secondary-container`, `surface-container-low/…/highest`, `outline(-variant)`, `error(-container)`) are `out` properties of `Theme`, DERIVED from the 15 theme tokens (`mix()`), so theme packages need no new keys; identical copies in home.slint and quick_menu.slint. Radii come from the `Shape` global (4/8/12/16/28 px). Grammar: rows/cards = tonal surface, focus = `secondary-container` + `primary` outline (cards: offset 3 px ring + soft glow); rail items = pill active indicator; switches = M3 switch; buttons = full-shape tonal, filled `primary` when focused, `error` roles when destructive; dialogs/dropdowns = `surface-container-high`, large/extra-large shape, no outline; QM slider = thick track split by a bar handle; keycaps = tonal badges; double-press confirmations ("armed", user request 2026-10-08) never put the prompt beside the title: the armed element itself switches to the error roles and carries the prompt on a second line inside it (`SettingsSelectableRow.armed` with the prompt in `detail`, `GenRow.armed` set by `apply_rows` from the armed key, `SettingsActionButton.armed`+`prompt`, QM `QmRow.armed`+`prompt` (game rows, Quit and Close Application, SYSTEM Restart and Power Off), Power OSD `PowerChoice` (Quick Menu)); weights 500/600 (700 only for the wordmark). Covers are rounded to the M3 medium shape: `max(12 px, h*0.06)` in Slint and in `library.rs` (`request_cover`) — keep both equal. `Theme` and `Shape` live in `ui/theme.slint` (imported by home.slint and its components, re-exported by home.slint for Rust/ui-shot); the Quick Menu keeps identical copies.
- Text entry (user request 2026-10-08): ONE text field everywhere, `TextEntryField` in `components/virtual_keyboard.slint` (label = what is entered, 19 px bold, centred, above an M3 filled field; content as children; field 72 px high, user request 2026-10-09) with an identical copy `QmTextEntryField` in quick_menu.slint; keys `KeyboardKey`/`QmKey` identical (tonal `surface-container-high`, focused = `primary`). The system keyboard sheet (settings-view 6) sits on the action bar with its own height (`content-height`, 280 px); Shift (key or `face_north`, hint "Uppercase" i18n 791) cycles off → one letter → Caps Lock (`keyboard-caps`, bar under the key) → off on the letter page of `text` AND `password` fields, the keys show the case (before 2026-10-09 password fields typed uppercase but never showed it); the page title above keeps the page it was opened from (`settings-title-view` = `keyboard-return-view`), the field label is `keyboard-title` (always localized: `open_system_keyboard` callers pass `tr()`). The QM Web keyboard surface is 270 px (`KEYBOARD_SURFACE_HEIGHT`), label "Web", text end kept visible. Headless scenes `keyboard`, `keyboard_caps`, `keyboard_ember`, `qm_keyboard`.
- Charging bolt (Home and QM `BatteryGlyph`): `bolt-outline.svg` coloured `Theme.background` under `bolt.svg` coloured `Theme.accent`; Battery Saver (effective profile) colours the battery glyph `Theme.warning` in Home and in the QM.

## Settings architecture (§13)
One visual grammar in every section. No separate fake preview: a highlighted category's right pane renders the REAL page (same state/model/layout/values); entering only changes focus/interactivity. Settings → Gaming (user decisions 2026-10-07/08, EPIC-005): RetroAchievements (USER); ScreenScraper account, Get Metadata for All Games and BIOS Files (DEVICE), the ScreenScraper rows directly on the page; emulator configuration is never duplicated there (per-game overrides in Game Settings, everything else in RetroArch Advanced).

## Settings structure (user request 2026-10-08)
Every category is split into sections (sticky header = section of the first visible row, inline headers below, each with its USER/DEVICE chip); sub-pages keep the section they were opened from.
- General: PROFILE (Profile, Language, Theme) | USERS | DATE & TIME | KEYBOARD. Profile page: Username, Profile Picture, Backup & Restore.
- Connectivity: WI-FI | BLUETOOTH | SERVICES (from row 6, the services themselves: SSH, SMB, Web Administration toggles, Password, Regenerate Password, Syncthing → page 66; user request 2026-10-08, no Remote/Online Services sub-pages; rows = `connectivity-services` GenRows built by `gameui.rs` `service_rows`). Software Update lives only in System (row 6).
- Controllers & Input: CONTROLLERS (Player Assignment, Controllers) | RUMBLE & LIGHTING (Internal Rumble, RGB Lighting).
- Gaming: GAMING (USER, row 0) | LIBRARY (DEVICE, from row 1); rows = `gaming-rows` GenRows from `gameui.rs`. BIOS Files page: YOUR SYSTEMS | OTHER SYSTEMS.
- Display & Audio: DISPLAY (Brightness, Color Temperature only when supported) | AUDIO (Audio Output, Volume, Applications, Home Music, Test Sound) | SOUNDS (System Sounds, Navigation Sounds, Power Sounds). Rust maps rows by function (`DaRow`, `display_audio_row`) because Color Temperature shifts the rows below it; section starts come from `da-audio-start`/`da-sounds-start`.
- System: POWER (0-4) | STORAGE & SOFTWARE (5 Storage, 6 Software Update, 7 System Information) | TROUBLESHOOTING (8 Diagnostics, 9 Recovery, 10 Reset System Settings).
- Mechanics: rows/headers use `sec-row-y(k, scroll, a, b, c)`/`sec-row-visible` (a, b, c = first rows of the later sections); Rust scrolls with `sectioned_scroll()` (calls the Slint `sec-row-visible`, keeps one row of context). New sectioned pages reuse both instead of bespoke row/scroll functions.

## UI architecture notes (§37.3)
- Settings live inside `package/nuubos/nuubui-home/src/ui/home.slint` (no separate package). Navigation/state in `src/main.rs`; `settings-view` integers are documented in home.slint.
- Every page shows section label + USER/DEVICE chip (structure above).
- Settings visual grammar: components `SettingsCategory`, `SettingsSectionHeader` (label + localized USER/DEVICE chip), `SettingsSelectableRow` (value | toggle | chevron | avatar preview, optional detail line), `SettingsActionButton`, `SettingsHint`. All rows are placed with `srow-y(k, scroll, split)` and shown with `srow-visible(...)`; metrics (`settings-row-height`, `settings-row-step`, `settings-content-x/width`, visible-row counts) are derived from the logical window size. Never hard-code row y positions.
- Scroll offsets are computed in Rust with `guarded_scroll_offset(index, count, visible, current)`; row counts there must match the Slint page.
- Slint 1.18 codegen bug: very large array-of-struct literals in `for` with many conditional fields can produce Rust "value moved" errors; split into explicit elements.
- `renderer-software` ignores `border-radius` when clipping (rectangular clip only). Round shapes made of images must be masked in Rust: avatars go through `round_avatar()` in nuubui-home `main.rs` (centre square crop, downscale ≤384 px, anti-aliased rounded-square alpha, corner 22% = Slint frames `width * 0.22`) and are placed inside the ring inset by `border-width`.
- Headless snapshots: `tools/ui-shot/run.sh [en it ...]` renders Settings and Quick Menu scenes at 640x480/720x720/1280x720/1920x1080 into `output/ui-shot/<lang>/`. Use it to check layout before deploying.
- Quick Menu (`package/nuubos/nuubos-quick-menu`) is a separate layer-shell client with its own Slint platform. Default: GPU (`src/gpu.rs`, `GpuWindow` = WindowAdapter + `FemtoVGRenderer`, one GLES context per window via glutin EGL on the libwayland `client_system` backend, `wl_egl_window`, swap interval 0, EGL surface detached before the wl_surface is destroyed). Fallback (no EGL or `NUUBOS_UI_RENDERER=software`): software renderer into two persistent wl_shm buffers (BGRA premultiplied `TargetPixel`, `RepaintBufferType::SwappedBuffers`, only dirty rows written + `damage_buffer`). The volume OSD alone uses a small bottom-anchored surface (`create_overlay(qh, true)`). All QM geometry/scroll lives in quick_menu.slint (`QmRow`, `QmSliderRow`, `QmSectionHeader`); Rust must not duplicate pixel positions.
- QM also draws the restart/poweroff curtain over fullscreen clients; Home draws the boot curtain.

## Localization mechanics (§12, §37.4)
- Catalogs: `package/nuubos/nuubos-localization/src/i18n/<lang>.lang` (`NNN=text`, index based) + `keys.txt`; validate with `sh validate-i18n.sh .` in that directory. Languages: de en es fr it nl pt.
- The Slint fallback arrays (`i18n-strings` in home.slint and quick_menu.slint) MUST match `en.lang` index-for-index; new strings are appended at the end of all catalogs and both arrays.
- Never compare service state against a translated string (`i18n-strings[n]`); compare raw service values.
## Splash, marquee, hint bars (§37.4)
- Lifecycle splash: one procedural design rendered by three renderers that MUST stay identical: `nuubos-splash.c` (kernel fbdev), the labwc first-frame patch, and `src/splash.rs` (duplicated in nuubui-home and nuubos-quick-menu; glyph table generated from the C source). Home/QM render it at the exact physical surface size and draw it 1:1 (no PNG assets, no per-frame scaling); the curtain splits on the splash accent line (`splash::geometry`).
- `MarqueeText` (identical copy in home.slint and quick_menu.slint) scrolls at a constant ~60 px/s (16 ms/px, min 1250 ms); `passes` = 2 (there and back) by default, 1 in notifications. The QM restarts a notification's marquee by blanking the labels and reading `toast-marquee-offset` before setting new text, and extends the card deadline to `toast-scroll-time` + 1.5 s.
- Bottom bars use the `ActionHint` component (keycap + label) inside HorizontalLayouts (`horizontal-stretch: 0` on hints, one stretching spacer) so spacing follows real label widths.

## GPU rendering and direct scan-out (§37.12, 2026-10-06)
- nuubui-home (Home + Settings + OOB) selects winit + `femtovg` (OpenGL ES 2 on Mesa Panfrost) in `select_renderer()`; the Quick Menu uses `gpu.rs` (§37.3). Both fall back to the software renderer if EGL fails; `NUUBOS_UI_RENDERER=software` forces it (export it in `nuubos-ui-launch` for an A/B). Skia is excluded (C++ build / prebuilt download, not reproducible offline). `tools/ui-shot` stays on the software renderer.
- Frames reach labwc as dmabufs (no wl_shm copy). A fullscreen Home with nothing above it is scanned out directly on the primary plane; any visible QM/OSD/notification surface means composition (labwc has no overlay-plane offload). Requirements, all needed: (1) labwc patch `0002-nuubos-release-boot-splash-on-first-map.patch` (the 0001 first-frame splash is ~250 scene rects that otherwise stay under every client); (2) `HideCursor` window rule in `/etc/xdg/labwc/rc.xml` (`WLR_NO_HARDWARE_CURSORS=1` makes even the 1 px `nuubos-hidden` cursor a software cursor, which forbids scan-out; a real pointer motion shows it again); (3) linux-dmabuf feedback: Panfrost first allocates Mali 16x16 U-interleaved tiled buffers (`0x0810000000000001`) the DE33 cannot scan; after wlroots' debounce frames the client reallocates LINEAR and scan-out starts (so it engages after ~10 rendered frames, not on the very first).
- Check: `cat /sys/kernel/debug/dri/0/state` — the active plane shows `format=AR24` `modifier=0x0` `size=` the client size when scanning out. For reasons, temporarily run `labwc -d` (edit `exec /usr/bin/labwc` in `/usr/bin/nuubos-ui-launch`, restore after) and grep `scan-out` in `/run/nuubos/labwc.log` (`disabled by software cursor`, `cannot be scanned out`, `Direct scan-out enabled`).
- Measured on RG40XX-V 640x480 (idle Home, QM closed): both processes still 0 wakeups/0 CPU. Private dirty memory GPU vs software: Home 57 vs 35 MB, QM 42 vs 9.5 MB (two GL contexts); system used 211 vs 163 MB of 983. Sharing one context between the two QM windows is a possible saving (FemtoVG assumes it owns its context: test before doing it).
- Measuring: `tools/ui-nav-bench.sh [pattern] [repeat] [interval]` replays a fixed navigation on the target through a virtual pad (`tools/uinput-nav`, /dev/uinput; also `M` and volume `+`/`-`) and prints per-thread CPU; compare runs of freshly restarted UIs only (a long-running instance measures ~5% lower). Profiling: a minimal aarch64 `perf` can be built from `output/h700/build/linux-7.2.8/tools/perf` (NO_LIBELF etc.) and samples resolved on the host with the toolchain `nm` against an unstripped build (`CARGO_PROFILE_RELEASE_STRIP=false`, `DEBUG=line-tables-only`, separate `--target-dir`).
- Measured 2026-10-06 (RG40XX-V, 48 moves): Home UI thread ~25% of a core on both renderers; FemtoVG re-tessellates the whole window every animation frame. Replacing the card strokes with stacked fills, or removing the 1 px tile border, made FemtoVG ~5% SLOWER: do not repeat. Black flash when QM/OSD/notifications close (composition→direct scan-out, user-confirmed by `WLR_SCENE_DISABLE_DIRECT_SCANOUT=1`): DE33 has no DBUFF latch, so the new ARGB format applied before the new address and labwc's XRGB buffer (X byte 0) was fetched as alpha 0 = black. Fix: kernel `0028-drm-sun4i-ignore-pixel-alpha-on-bottom-layer.patch` (zpos-0 layer uses layer alpha 0xff; identical output for premultiplied content over the black background). Hardware confirmation pending.
- Motion (user request 2026-10-09, "fluid animations"): strips, the Home column, grids and lists glide with the M3 emphasized curve `cubic-bezier(0.2, 0.0, 0.0, 1.0)` (strip 260 ms, column 300 ms, grid/list 260–280 ms); focus rings fade (`HomeFocusRing`, 140 ms opacity) instead of popping, tile/row fills animate 150 ms. Every Home card/tile and app-page row has `cache-rendering-hint: true` (FemtoVG layer: a scroll composites cached textures instead of re-tessellating; A/B 2026-10-09: 697 vs 768 UI ticks on `tools/ui-nav-bench.sh` default pattern, so keep it). Measured with `SLINT_DEBUG_PERFORMANCE=refresh_lazy,console` (must reach the process: the UI inherits labwc's environment, so for a one-off measurement wrap `/usr/bin/nuubui-home` and restart with `S50nuubos-ui stop` + `start`; `restart` is a no-op while labwc runs): 52–60 fps (mostly 59–60) during continuous navigation at 640x480. Total UI CPU rose from 473 to ~697 ticks per bench run only because the longer animations draw ~45 % more frames; per-frame cost is unchanged. Slint gotcha: an element without `x`/`y` is CENTRED in its parent (a full-width wash without `y: 0` became a band in the middle).
- Application pages (Moonlight 40/41, Steam Link 45; user request 2026-10-09 "like the Game Details page"): `AppPage` + `AppEntryRow` in home.slint, filled by `src/apppage.rs` (`refresh()` after every streamd snapshot, page change and input); moonlight.rs/steamlink.rs keep their index order (entries first, then actions) and also move with left/right on these pages. Hero = the app icon of the Home tile (`app-page-icon`), wash of the primary colour, kicker/title/meta/chips, PCs or PC applications as rows with a status pill, a large pairing PIN panel, the Steam Link download as a progress bar, actions as `DetailActionButton` pills with the focused item's caption under them. Stream Settings (42) stays a Settings list. Own icons `desktop.svg` (PC) and `plus.svg` (add) = DetailIcon 18/19 (nuubOS geometry, MIT, noted in the icons ATTRIBUTION). ui-shot scenes `moonlight_pcs`, `moonlight_actions`, `moonlight_pin`, `steamlink_absent`, `steamlink_installing`, `steamlink_installed` (ui-shot scenes share state: render these with their own ONLY when comparing).
- Software-renderer workarounds (`round_avatar()`, rounded covers in `library.rs`) stay: the fallback and ui-shot still need them and they cost nothing on the GPU.

## Themes (§37.21, EPIC-008)
- `export global Theme` (15 color tokens, defaults = built-in look) at the top of `home.slint` and `quick_menu.slint`; the most used literals were replaced (`Theme.accent` …). Remaining literals are fixed design colors. New UI code must use the tokens for accent/text/surface colors. ui-shot re-exports `Theme` (`tools/ui-shot/shots.slint`); scene `theme_ember`.
- Package `nuubos-themes`: `nuubos-themectl list|validate|install SRC|remove ID|select USER ID|selected USER`; built-ins `/usr/share/nuubos/themes/{nuubos,ember,mint,graphite}/theme.conf` (own colors, MIT); user packages `/userdata/themes/<id>`; selection `THEME=` in `/state/users/<id>/settings.conf`. Format and token table: `docs/themes.md`. Host test `sh package/nuubos/nuubos-themes/tests/themes.sh`.
- Home `src/themes.rs`: applies the active user's tokens at startup/user switch (`apply_users`), never in safe mode; General row 2 Theme opens a dropdown that previews each theme live while moving and restores on Back. Quick Menu reads the tokens at every menu open (`refresh_theme`) and applies them to the notification card too. Files offers Install Theme on `.tar`/folders with `theme.conf`.
- Not done: theme removal UI (themectl `remove` exists), preview images, fonts/sounds/layout in themes.
## Keyboard navigation (§37.24, EPIC-023)
- nuubUI accepts a physical keyboard: the `keyboard-scope` FocusScope in home.slint maps arrows/Enter/Space/Esc/Backspace/Tab to `keyboard-action`, which goes through the same `route_input_action()` in `main.rs` as inputd actions (no second navigation path). `focus-navigation()` gives the scope focus back after a text field (view 6 keyboard) closes. Text entry keeps the on-screen QWERTY sheet with physical key support.
