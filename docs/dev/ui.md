# UI: visual grammar, Settings, rendering, localization, themes

Cross-cutting rules (responsive, controller-first, no idle redraw, marquee, localization): CLAUDE.md.

## Visual direction (§11)
Reference: the nuubOS "Small System. Big Adventures." mockup: dark/matte console UI, hero artwork on Home, minimal top bar, Recently Played with cover art and blue focus glow, selected-game metadata, Systems & Collections, Applications, controller hints at the bottom, clean console presentation. ## Material 3 (user request 2026-10-08)
The UI follows Material Design 3 on the nuubOS dark/matte look with the blue accent (§11 stays the reference). Colour roles (`primary`, `primary-container`, `secondary-container`, `surface-container-low/…/highest`, `outline(-variant)`, `error(-container)`) are `out` properties of `Theme`, DERIVED from the 15 theme tokens (`mix()`), so theme packages need no new keys; identical copies in home.slint and quick_menu.slint. Radii come from the `Shape` global (4/8/12/16/28 px). Grammar: rows/cards = tonal surface, focus = `secondary-container` + `primary` outline (cards: offset 3 px ring + soft glow); rail items = pill active indicator; switches = M3 switch; buttons = full-shape tonal, filled `primary` when focused, `error` roles when destructive; dialogs/dropdowns = `surface-container-high`, large/extra-large shape, no outline; QM slider = thick track split by a bar handle; keycaps = tonal badges; double-press confirmations ("armed", user request 2026-10-08) never put the prompt beside the title: the armed element itself switches to the error roles and carries the prompt on a second line inside it (`SettingsSelectableRow.armed` with the prompt in `detail`, `GenRow.armed` set by `apply_rows` from the armed key, `SettingsActionButton.armed`+`prompt`, QM `QmRow.armed`+`prompt` (game rows, Quit and Close Application, SYSTEM Restart and Power Off), Power OSD `PowerChoice` (Quick Menu)); weights 500/600 (700 only for the wordmark). Covers are rounded to the M3 medium shape: `max(12 px, h*0.06)` in Slint and in `library.rs` (`request_cover`) — keep both equal. `Theme` and `Shape` live in `ui/theme.slint` (imported by home.slint and its components, re-exported by home.slint for Rust/ui-shot); the Quick Menu keeps identical copies.
- Text entry (user request 2026-10-08): ONE text field everywhere, `TextEntryField` in `components/virtual_keyboard.slint` (label = what is entered, 19 px bold, centred, above an M3 filled field; content as children; field 72 px high, user request 2026-10-09) with an identical copy `QmTextEntryField` in quick_menu.slint; keys `KeyboardKey`/`QmKey` identical (tonal `surface-container-high`, focused = `primary`). The system keyboard sheet (settings-view 6) sits on the action bar with its own height (`content-height`, 280 px); Shift (key or `face_north`; its hint names what the next press does: "Uppercase" 791 → "Caps Lock" 1337 → "Lowercase" 1338, user report 2026-10-21: one press capitalises one letter only, so Caps Lock "did not work"; German shortened to Groß/Feststellen/Klein for 640x480; the keyboard sheet hides the Navigate hint for room) cycles off → one letter → Caps Lock (`keyboard-caps`, bar under the key) → off on the letter page of `text` AND `password` fields, the keys show the case (before 2026-10-09 password fields typed uppercase but never showed it); the page title above keeps the page it was opened from (`settings-title-view` = `keyboard-return-view`), the field label is `keyboard-title` (always localized: `open_system_keyboard` callers pass `tr()`). The QM Web keyboard surface is 270 px (`KEYBOARD_SURFACE_HEIGHT`), label "Web", text end kept visible. Headless scenes `keyboard`, `keyboard_caps`, `keyboard_ember`, `qm_keyboard`.
- Charging bolt (Home and QM `BatteryGlyph`): `bolt-outline.svg` coloured `Theme.background` under `bolt.svg` coloured `Theme.accent`; Battery Saver (effective profile) colours the battery glyph `Theme.warning` in Home and in the QM.

## Settings architecture (§13)
One visual grammar in every section. No separate fake preview: a highlighted category's right pane renders the REAL page (same state/model/layout/values); entering only changes focus/interactivity. Settings → Gaming (user decisions 2026-10-07/08, EPIC-005): RetroAchievements (USER); ScreenScraper account, Get Metadata for All Games and BIOS Files (DEVICE), the ScreenScraper rows directly on the page; emulator configuration is never duplicated there (per-game overrides in Game Settings, everything else in RetroArch Advanced).

## Settings structure (user request 2026-10-08, reorganized 2026-11-09 for RC5: one place per setting, everyday settings one step away, groups by what the user wants to do)
Every category is split into sections (sticky header = section of the first visible row, inline headers below, each with its USER/DEVICE chip); sub-pages keep the section they were opened from.
- General: PROFILE (Profile, Language, Theme) | USERS | DATE & TIME | KEYBOARD. Profile page: Username, Profile Picture (backup moved to System › Troubleshooting, user request 2026-10-11).
- Connectivity: WI-FI | BLUETOOTH | SCREEN CASTING (rows 6-8, USER, only while castd runs, `conn-services-start`/`conn-split3`) | SERVICES (the services themselves: SSH, SMB, Web Administration toggles, Password, Regenerate Password; no Remote/Online Services sub-pages; rows = `connectivity-services` GenRows built by `gameui.rs` `service_rows`, first index `services_first()`). Software Update lives only in System.
- Controllers & Input: CONTROLLERS (Player Assignment, Controllers, Swap Confirm/Back, Game Hotkeys) | RUMBLE & LIGHTING (Vibration Intensity and Test Rumble directly on the page, RGB Lighting). Page 16 no longer exists.
- Gaming (view 68, USER): GAMING (System Settings) | PICTURE (Position, Bezels, CRT) | SAVES (Slots, Rotate, Syncthing) | EXTRAS (RetroAchievements, Boot Screens, Overlay, RetroArch row). Library (view 78, rail index 4, DEVICE): LIBRARY (Scan, Show Unavailable, Wrap) | COVERS & INFO (source, region, account, the scraping runs) | FILES (BIOS, Cheats). One page, one `gaming-rows` model: `gaming_rows` builds every row, `page_rows` keeps those of the page in `GAMING_PAGE` order and sets `gaming-split*`, `gaming-label*`, `gaming-scope`; scroll from `sectioned_scroll` like the other sectioned pages. Sub-pages: BIOS Files YOUR SYSTEMS | OTHER SYSTEMS.
- Game Settings and System Settings (one builder, `settings_rows`, `GAME_SETTINGS_ORDER`, `game_settings_sections`): PICTURE (Aspect, Scaling, Filter) | SPEED (Resolution, Frameskip, Accuracy; absent when the core has none) | EMULATOR (Get More Emulators is the last entry of its list) | CONTROLS (Accessory, Controls, system link, Reset). Game Details: Game Settings right after Play. Home: North on a system tile opens its System Settings (`open_system_from_home`, Back returns to Home).
- Display & Audio: DISPLAY (Brightness, Color Temperature only when supported) | AUDIO (Audio Output, Volume, Volume Button Step, Applications, Home Music and its volume, Test Sound) | SOUNDS (System, Navigation, Notification, Power). Rust maps rows by function (`DaRow`, `display_audio_row`) because Color Temperature shifts the rows below it; section starts come from `da-audio-start`/`da-sounds-start`.
- System: STORAGE & SOFTWARE (0 Storage, 1 Backup, 2 Software Update, 3 System Information) | TROUBLESHOOTING (4 Diagnostics, 5 Recovery). Rail order: General, Connectivity, Controllers & Input, Gaming, Library, Display & Audio, Power, System. Web panel: same grouping (`library-settings` page; Game Hotkeys under `controllers/hotkeys`).
- Mechanics: rows/headers use `sec-row-y(k, scroll, a, b, c)`/`sec-row-visible` (a, b, c = first rows of the later sections); Rust scrolls with `sectioned_scroll()` (calls the Slint `sec-row-visible`, keeps one row of context). New sectioned pages reuse both instead of bespoke row/scroll functions.

## UI architecture notes (§37.3)
- Settings live inside `package/nuubos/nuubui-home/src/ui/home.slint` (no separate package). Navigation/state in `src/main.rs`; `settings-view` integers are documented in home.slint.
- Every page shows section label + USER/DEVICE chip (structure above).
- Applications never show the Settings rail (user request 2026-10-10): entry pages are `AppPage` (`app-page-shown`, follows `settings-title-view` so the page stays behind its keyboard); application pages built from Settings rows (Moonlight Stream Settings 42, Web 67) use the full-screen app shell (`app-shell` in home.slint): no rail/shell title, pane at x 0, centred column ≤1100 px, AppPage colour wash, kicker = app name, page title, optional meta line (`app-shell-meta`, moves `settings-section-y` 62→78). The global choice sheet over AppPage/Game Details is the outer one (the pane's sheet cannot rise above a sibling page).
- Settings visual grammar: components `SettingsCategory`, `SettingsSectionHeader` (label + localized USER/DEVICE chip), `SettingsSelectableRow` (value | toggle | chevron | avatar preview, optional detail line), `SettingsActionButton`, `SettingsHint`. All rows are placed with `srow-y(k, scroll, split)` and shown with `srow-visible(...)`; metrics (`settings-row-height`, `settings-row-step`, `settings-content-x/width`, visible-row counts) are derived from the logical window size. Never hard-code row y positions.
- Scroll offsets are computed in Rust with `guarded_scroll_offset(index, count, visible, current)`; row counts there must match the Slint page.
- Slint 1.18 codegen bug: very large array-of-struct literals in `for` with many conditional fields can produce Rust "value moved" errors; split into explicit elements.
- `renderer-software` ignores `border-radius` when clipping (rectangular clip only). Round shapes made of images must be masked in Rust: avatars go through `round_avatar()` in nuubui-home `main.rs` (centre square crop, downscale ≤384 px, anti-aliased rounded-square alpha, corner 22% = Slint frames `width * 0.22`) and are placed inside the ring inset by `border-width`.
- Headless snapshots: `tools/ui-shot/run.sh [en it ...]` renders Settings and Quick Menu scenes at 640x480/720x720/720x480/1280x720/1920x1080 (720x720 and 720x480 at scale 1.125, as on the device) into `output/ui-shot/<lang>/`. Use it to check layout before deploying.
- Quick Menu (`package/nuubos/nuubos-quick-menu`) is a separate layer-shell client with its own Slint platform. Default: GPU (`src/gpu.rs`, `GpuWindow` = WindowAdapter + `FemtoVGRenderer`, one GLES context per window via glutin EGL on the libwayland `client_system` backend, `wl_egl_window`, swap interval 0, EGL surface detached before the wl_surface is destroyed). Fallback (no EGL or `NUUBOS_UI_RENDERER=software`): software renderer into two persistent wl_shm buffers (BGRA premultiplied `TargetPixel`, `RepaintBufferType::SwappedBuffers`, only dirty rows written + `damage_buffer`). The volume OSD alone uses a small bottom-anchored surface (`create_overlay(qh, true)`). All QM geometry/scroll lives in quick_menu.slint (`QmRow`, `QmSliderRow`, `QmSectionHeader`); Rust must not duplicate pixel positions.
- QM also draws the restart/poweroff curtain over fullscreen clients; Home draws the boot curtain.

## Localization mechanics (§12, §37.4)
- Catalogs: `package/nuubos/nuubos-localization/src/i18n/<lang>.lang` (`NNN=text`, index based) + `keys.txt`; validate with `sh validate-i18n.sh .` in that directory. Languages (2026-10-15, user request "aggiungi più lingue… proprio tutto"): en it fr de es es-419 pt pt-br nl pl cs sv da nb fi hu ro tr el ru uk id vi th hi ja zh-cn zh-tw ko (29). The 22 added that day were written by Claude: they need a native-speaker review. Plural-sensitive strings use neutral forms ("Игр: {0}"). Not added: Arabic/Hebrew/Persian (the UI has no right-to-left layout).
- A new language touches: the catalog (+ web admin block in `nuubos-remote/src/web/www/i18n.js` and `LANGUAGES` in `pages.js`), `UI_LANGUAGES`/`language_name` (Home `main.rs`), the OOB `greetings` (home.slint, same order), `LANGS`/`langs[]` in `localizationd.c`, admind `lang.set` allowlist, emud `retroarch_language` (RETRO_LANGUAGE_* ids, English when RetroArch lacks it), streamd `steamlink_locale` (Steam language names), scraper/libraryd (regional codes use the prefix: `zh-cn`→`zh`), webd (`zh-cn`→`zh_CN`).
- Dates: strings 1287–1298 are the months as written inside a date (case/genitive), 1299 the date pattern (`{0}` day, `{1}` month, `{2}` year), 1300 with the weekday (`{3}`); `datetime.rs` `format_date`. Never build a date by concatenation.
- Fonts: Cantarell covers Latin/Cyrillic/Vietnamese; Slint (parley + harfrust shaping, fontconfig fallback) takes the rest from DejaVu (Greek) and package `nuubos-fonts-noto` (Noto Sans CJK Regular/Bold OTC, Noto Sans Thai, Noto Sans Devanagari; OFL-1.1, ~41 MB in `/usr/share/fonts/noto`). After deploying fonts by hand run `fc-cache -f`. Checked on the CubeXX 720x720 2026-10-15: ja, ru, th, hi render and shape correctly; the Russian hint bar overflowed until 523 was shortened (long words: check the 640x480 hint bar).
- The Slint fallback arrays (`i18n-strings` in home.slint and quick_menu.slint) MUST match `en.lang` index-for-index; new strings are appended at the end of all catalogs and both arrays.
- Never compare service state against a translated string (`i18n-strings[n]`); compare raw service values.

Bezels use it too (emulation.md). The motto "Small System. Big Adventures." stays (user request): under the splash track at boot only, same dot style at pitch cell/3 (5x7 letters, `nuubos_motto`/`MOTTO`), dimmed (55 % text over background).
- Lifecycle splash (redesigned 2026-10-10, user request "new UX + RGB in sync"): the dot-matrix logo above a pill track in the surface colour (+ the motto at boot), on the Mood background. ONE renderer, `package/nuubos/nuubos-splash/src/nuubos-splash-render.h` (integer only: 1/8 px coordinates, 4x4 samples, exact squared distances; dot grid aligned to whole pixels, pitch = 11 % of the height / 7, at most 80 % of the width / 37), used by `nuubos-splash` (kernel fbdev, S00/K11/lifecycle-finalize) and by labwc's first frame (patch 0001: one scene buffer, kept at the output's logical size by patch 0005: the panel scale nuubos-wl-output-apply sets after the first frame (1.125 on 720x720) used to enlarge it by 12.5 % until Home drew, a jump at every boot, user report 2026-10-11; `labwc.mk` copies the header into `src/` as a PRE_BUILD hook, so a renderer change needs `labwc-rebuild` only), and a line-by-line Rust port `src/splash_core.rs` (identical copies in nuubui-home and nuubos-quick-menu). `sh tools/splash-check/run.sh` checks C = Rust to the bit (6 sizes x 4 modes x 2 palettes) and that the two Rust copies match: run it after any change. Modes: boot (logo + empty track + motto), reboot (logo + empty track), poweroff (logo dimmed 35 % toward the background, no track), full (accent track). `nuubos-splash --ppm FILE W H MODE [PALETTE]` renders on the host (pass all arguments: without them it draws on /dev/fb0).
- Palette: `/etc/nuubos/splash.palette` (rootfs: the kernel splash runs before STATE is mounted), written by `nuubos-themectl splash-palette` (active user's Mood; only when it changes; nothing with nobody signed in), which Home calls in `themes::apply_active` (start, user switch, Mood change). With nobody signed in (user picker) Home applies the last user's Mood (else the default user's; usersd `last_user`; the picker background is Theme.background), and lightingd takes its accent from the palette (its no-user id is "default", not empty: the first fallback missed it), so picker, boot splash and boot LEDs agree (user report 2026-10-10). Built-in nuubOS colours when missing (e.g. after an image update). Home reads the palette once at start for the boot animation (`BOOT_PALETTE`), so it continues what kernel and labwc showed.
- Animations: `splash::frame(kind, ms)` in `src/splash.rs` (same file in Home and QM) gives every frame (raster alphas + accent pill on the track); constants `BOOT_FILL_MS` 700, `BOOT_FADE_MS` 320, `OUT_FADE_MS` 280, `RESTART_SWEEP_MS` 900 x 2 (slowed on user feedback: the LED laps were too fast), `POWEROFF_DRAIN_MS` 650. boot: the track fills from its centre, then the splash fades out over Home; reboot: fade in, an accent segment sweeps the track twice, the reboot raster stays; poweroff: fade in with a full track that drains to the centre while the wordmark dims to the poweroff raster. Home drives it with a 16 ms Timer (`run_splash`; a second identical announcement from lifecycle-finalize is ignored), the QM in `animate_shutdown`. The splash layer has z 1000-1002: the user picker (z 180), OOB (150/190) and safe mode (185/186) used to cover it, so with the picker at boot the animation never showed (user report 2026-10-10; the old curtain had the same bug). The boot animation starts 120 ms after Home's first rendered frame (rendering notifier; 400 ms timer on the software renderer), not at a fixed time after process start. The two restart sweeps follow one ease over both (no stop between them), like the LED laps. The final frames equal what `nuubos-splash --prepare` draws for the scanout handoff; `nuubos-lifecycle-finalize` waits 2.15 s (reboot) / 1.00 s (poweroff) for Home.
- RGB in step: nuubos-lightingd `Lifecycle(boot|restart|reboot|poweroff)` plays SHAPE_BOOT (ring lights from the BOTTOM LED up both sides and closes at the top, `RING_BOTTOM` 0.375 = position 3 on the RG40XX-V where position 0 is the upper right LED, clockwise, checked with `nuubos-rgbctl locate 0`; CubeXX rings still to check; then crossfades back to the user's effect), SHAPE_RESTART (effect fades, a comet runs two continuous laps under one ease, LEDs off) and SHAPE_POWEROFF (full accent ring drains to position 0 while dimming, LEDs off) with the same constants (`SPLASH_*_MS` in lightingd.c — keep equal to splash.rs). Home sends `boot` when its boot animation starts (once per boot: `/run/nuubos/lighting-welcomed`; the old welcome at service start is gone), the QM runs `lifecycle-lighting reboot|poweroff` when its animation starts, nuubos-systemd sends `restart|poweroff` before announcing the mode to Home; a second call during/after the shape changes nothing. All need the user's power signal category.
- Verified 2026-10-10 on RG40XX-V: target rasters, a full restart (Home path) with the Mood colours, boot animation and `boot` phase. Not yet checked by eye: animation smoothness, LED timing against the screen, the Quick Menu/Power OSD path, HDMI.
- `MarqueeText` (identical copy in home.slint and quick_menu.slint) scrolls at a constant ~60 px/s (16 ms/px, min 1250 ms); `passes` = 2 (there and back) by default, 1 in notifications. The QM restarts a notification's marquee by blanking the labels and reading `toast-marquee-offset` before setting new text, and extends the card deadline to `toast-scroll-time` + 1.5 s.
- Bottom bars use the `ActionHint` component (keycap + label) inside HorizontalLayouts (`horizontal-stretch: 0` on hints, one stretching spacer) so spacing follows real label widths.

## GPU rendering and direct scan-out (§37.12, 2026-10-06)
- nuubui-home (Home + Settings + OOB) selects winit + `femtovg` (OpenGL ES 2 on Mesa Panfrost) in `select_renderer()`; the Quick Menu uses `gpu.rs` (§37.3). Both fall back to the software renderer if EGL fails; `NUUBOS_UI_RENDERER=software` forces it (export it in `nuubos-ui-launch` for an A/B). Skia is excluded (C++ build / prebuilt download, not reproducible offline). `tools/ui-shot` stays on the software renderer.
- Frames reach labwc as dmabufs (no wl_shm copy). A fullscreen Home with nothing above it is scanned out directly on the primary plane; any visible QM/OSD/notification surface means composition (labwc has no overlay-plane offload). Requirements, all needed: (1) labwc patch `0002-nuubos-release-boot-splash-on-first-map.patch` (the 0001 first-frame splash is ~250 scene rects that otherwise stay under every client); (2) `HideCursor` window rule in `/etc/xdg/labwc/rc.xml` (`WLR_NO_HARDWARE_CURSORS=1` makes even the 1 px `nuubos-hidden` cursor a software cursor, which forbids scan-out; a real pointer motion shows it again); (3) linux-dmabuf feedback: Panfrost first allocates Mali 16x16 U-interleaved tiled buffers (`0x0810000000000001`) the DE33 cannot scan; after wlroots' debounce frames the client reallocates LINEAR and scan-out starts (so it engages after ~10 rendered frames, not on the very first).
- Check: `cat /sys/kernel/debug/dri/0/state` — the active plane shows `format=AR24` `modifier=0x0` `size=` the client size when scanning out. For reasons, temporarily run `labwc -d` (edit `exec /usr/bin/labwc` in `/usr/bin/nuubos-ui-launch`, restore after) and grep `scan-out` in `/run/nuubos/labwc.log` (`disabled by software cursor`, `cannot be scanned out`, `Direct scan-out enabled`).
- Home window destroyed during games (2026-10-29, perf-power.md memory): Home kept ~88 MB of GPU memory (417 BOs on the CubeXX: 72 x ~460 KB cover textures of the 64-cover LRU, card layers, glyph atlas) while RetroArch covered it. `home_window_shown()` (main.rs) hides the window when a game or port session starts and shows it again (fullscreen) when emud reports `quitting=1` (the Quick Menu's closing screen covers the switch) or at the session end; on Wayland Slint's `hide()` destroys the surface and suspends the FemtoVG renderer (`clear_graphics_context`), so `ui.run()` became `show()` + `run_event_loop_until_quit()`. Measured: during God of War Home's BOs are purgeable and get purged by the kernel (debugfs `dri/1/gems` state 0x4; ~8-10 MB stay: exported window buffers, the heap): ~80 MB more for the game. Return: normal quit, no visible change (closing screen until Home is up); a session ending without a quit (crash, kill -9) shows black ~0.4-0.5 s before Home (old build: Home at ~0.8 s, new ~1.3 s after RetroArch died). Check: Home BOs per state with `awk '$1 ~ /nuubui/' /sys/kernel/debug/dri/1/gems` (debugfs mounted); fdinfo `drm-resident-memory` still counts purged BOs.
- Measured on RG40XX-V 640x480 (idle Home, QM closed): both processes still 0 wakeups/0 CPU. Private dirty memory GPU vs software: Home 57 vs 35 MB, QM 42 vs 9.5 MB (two GL contexts); system used 211 vs 163 MB of 983. Sharing one context between the two QM windows is a possible saving (FemtoVG assumes it owns its context: test before doing it).
- Measuring: `tools/ui-nav-bench.sh [pattern] [repeat] [interval]` replays a fixed navigation on the target through a virtual pad (`tools/uinput-nav`, /dev/uinput; also `M` and volume `+`/`-`) and prints per-thread CPU; compare runs of freshly restarted UIs only (a long-running instance measures ~5% lower). Profiling: a minimal aarch64 `perf` can be built from `output/h700/build/linux-<version>/tools/perf` (NO_LIBELF etc.) and samples resolved on the host with the toolchain `nm` against an unstripped build (`CARGO_PROFILE_RELEASE_STRIP=false`, `DEBUG=line-tables-only`, separate `--target-dir`).

Replacing the card strokes with stacked fills, or removing the 1 px tile border, made FemtoVG ~5% SLOWER: do not repeat. Hardware confirmation pending.

- HDMI 1080p (2026-10-09, user requirements: 60 fps, render 720p and upscale like games, nothing CRT-like in nuubUI): (1) Root cause of the slowness: Mesa Panfrost chose the two COARSEST tiler hierarchy levels on Mali-G31 (only 2 levels, `Tiler:0x209`), so every primitive was binned at >= 512 px and walked by every 16 px tile of the bin: ~0.17 ms of fragment time per draw for an 8 px square, ~0.55-0.8 ms for a rounded shape, independent of size; Home's many small shapes (hint dots, chips, icons) made it fill-bound-looking (cost linear in screen size). - Slint 1.18 FemtoVG gotchas (read in i-slint-core `item_rendering.rs` / renderer `itemrenderer.rs`): `Opacity` and `Layer` (`cache-rendering-hint`) items are rendered even when fully clipped out; an `opacity` < 1 (0 included) on an element with more than one child, or with a child that has children, renders the subtree into an offscreen layer every frame (mid-frame FBO switch, expensive on the tile-based Mali); a cached layer is released only when its item is destroyed or visited with the hint off, so clipped-out items keep their textures. Never put `opacity` on a per-card subtree; virtualize long `for` lists (instantiate only near the viewport). With the ring fixed, card layers are a net win on HDMI too (A/B 1080p: Home 20-28 fps with layers vs 13-20 without; grid 15-27 vs 10-14): keep `cache-rendering-hint: true`.
- Frame pacing (2026-10-09, HDMI 720 lines; measured with `WAYLAND_DEBUG=client` commit intervals = missed vsyncs, and per-frame CPU bursts from `perf record -t <UI tid>` timestamps): misses came from Home's own frames exceeding 16.7 ms, not from the GPU (~10 ms) or labwc (frame done right after its commit). Causes and fixes: (1) Slint marks every binding that depends on a changed property dirty even when its value is unchanged, so `focused: root.active && i == root.index` dirtied EVERY cached card/tile layer on each move (18-22 layer re-renders per row change, logged with a temporary eprintln in `render_layer`): focus now lives in the model (`HomeCard.focused`), set by `library.rs` `sync_focus()` only on the rows that change (2 layer re-renders per move). (2) No animated property inside a cached layer (`animate background`, `MarqueeText`, the card's own `HomeFocusRing` fade): it ties the layer to the animation driver, re-rendering it on the first frame after the UI went idle; tiles switch colour instantly, use `MarqueeText` only while focused, and the ring is drawn outside the card (`draw-ring: false`, the card's internal ring is not instantiated). (3) Row dimming of tiles is a scrim outside the layers (`visible: !active`), not an ink change. (4) Slint patch `patches/packages/i-slint-core/0001` (vendored by a `nuubui-home.mk` POST_RSYNC hook from the offline cargo cache + `[patch.crates-io]`): `render_layer` no longer crops a layer to the current clip; the clip is not a tracked dependency, so a card cached while partly scrolled out stayed cut (user bug 2026-10-09: first Recently Played cover cut on the left). Remaining: the first frame after idle still costs ~25-35 ms (CPU; GPU runtime PM and governors ruled out). Dead ends: CPU `performance` governor (no change), femtovg convexity patch (rounded rects are already convex), tiles without layers (worse).
