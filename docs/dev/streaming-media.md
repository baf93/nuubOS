# PC streaming, Steam Link, media playback, Web Mode

## Moonlight (§37.14, EPIC-025)
- Packages: `package/streaming/moonlight-embedded` (2.7.1 + nuubOS patches: Wayland/V4L2 request platform, avahi optional, low-latency ALSA, `-gamepad`/`-noquitcombo`, `-control` channel) and FFmpeg 7.1.5 (Buildroot bump `patches/buildroot/0002-ffmpeg-7.1.5-buildroot-2026.08.patch`, applied by `scripts/prepare-buildroot.sh` with the graphics patch) + Kwiboo `v4l2-request-n7.1.3` series + nuubOS 0015 (a DRM hwdevice is mapped to the V4L2 request device: Moonlight and Steam Link pass DRM) + 0016 (DRM device without a path) in `patches/packages/ffmpeg/7.1.5/` (defconfig: h264/hevc decoders + hwaccels only). Buildroot package patches must apply with fuzz 0 (`patch -F0`); a version bump leaves the old `libavcodec.so.60`/`libavutil.so.58` in `output/h700/target` until removed by hand. Design, measurements and licences: `package/streaming/README.md`. `external.mk` orders FFmpeg after udev and keeps PipeWire's FFmpeg plugin off (`-Dffmpeg=disabled`, meson keeps the last `-D`).
- Video path: Cedrus (stateless V4L2, `/dev/video0` + `/dev/media0`) → NV12 dma-buf → `zwp_linux_dmabuf_v1` subsurface composited by labwc; no CPU copy, no client GL. Qualify without a host: `tools/moonlight-vdec/run.sh 640x480 60 h264|hevc` (encodes a clip on the host, runs the real renderer on target, prints decode stats; grab the screen meanwhile).
- Service `nuubos-streamd` (package `nuubos-streaming`, `S49nuubos-streamd`, socket `/run/nuubos/streamd.sock`, log `/run/nuubos/streamd.log`, Moonlight stderr `/run/nuubos/moonlight.log`, CLI `nuubos-streamctl status|watch|discover|add ADDR|remove|refresh|pair|pair-cancel|apps|launch HOST APP|quit [close]|stats|stats-watch|wake HOST|button home|quick-access|set KEY VALUE|pre-power`). Snapshot: `state=idle|starting|streaming|exiting`, settings, `discovering`, `pairing_host/pin`, `apps_host/state`, `host=id\tname\taddress\tpaired\tonline\tsaved\tprobing\twol\twaking`, `app=id\tname`, `end=1`. Moonlight runs as a child per operation (`status`/`pair`/`list`/`quit`/`unpair` with timeouts, `stream` with stdin control), in the active user's dir with `-keydir`; idle = poll without timeout.
- Per user: `/userdata/users/<id>/appdata/moonlight/{keys/,hosts.conf,settings.conf}` (client identity created by Moonlight on first use). Settings defaults live in `streamd.c` (`DEFAULT_*`: resolution auto = active screen capped 1080p, 60 fps, H.264, bitrate auto). Not part of Reset System Settings (per-user app data).
- Discovery: one-shot mDNS PTR query for `_nvstream._tcp.local` (legacy unicast replies) when the Moonlight page opens or on Search; no avahi.
- Session: like a game: inputd `GAMEPADS ON` connection for the stream's lifetime, Moonlight reads only `nuubOS Gamepad` devices (SDL mapping in `streamd.c` `GAMEPAD_MAPPING`, player = product id), Quick Menu button opens the QM (emulation chords are consumed and ignored), pre-power hook `55-streaming` ends the stream before Sleep/Restart/Power Off (the host app keeps running). Notifications `stream.paired|pair.failed|failed reason=unreachable|unpaired|app|start|connection`.
- UI: Home → Applications → Moonlight (`/usr/share/nuubos/applications/moonlight.app`, ID `moonlight` handled by `moonlight.rs`): application page (AppPage, `apppage.rs`) for settings-view 40 PCs / 41 PC (pairing PIN or applications); 42 Stream Settings = full-screen app shell (ui.md), keyboard purpose 10 adds a PC by address. Home input and Home Music follow `moonlight::STREAM_RUNNING` like `GAME_RUNNING`. Quick Menu over a stream: STREAM section (rows 15 Resume, 36 PC Home Button, 37 Steam Quick Access, 38 Performance Overlay, 16 Quit Stream, 17 Quit and Close Application with second press) and statistics sampled once when the menu opens (`STATS`). Headless: `tools/ui-shot/run.sh` renders `moonlight_*` and `qm_stream*` scenes.
- Pairing: `PAIR` shows a 4-digit PIN in nuubUI; the user enters it in Sunshine's web UI (PIN page) or GeForce Experience. Never run scripted `launch`/`quit` while the user may be streaming: check `nuubos-streamctl status` is idle.
## Steam Link (§37.15, EPIC-026)
- Valve's proprietary app, never in the image. `nuubos-streamd` downloads it on request with `/usr/lib/nuubos/nuubos-steamlink-get` (libcurl/zlib, `check | install <root> | remove <root>`, `@progress/@latest/@done/@error` lines): build pointer `https://media.steampowered.com/steamlink/rpi/trixie/arm64/public_build.txt`, streamed gzip+tar extraction into `/userdata/steamlink/.staging` (exFAT: symlinks/hardlinks become copies), swapped to `/userdata/steamlink/app`. Target BusyBox `tar` has no `-z` and cannot create symlinks on USERDATA. Requires `ca-certificates` (added) for TLS.
- Runtime in the image (`package/streaming/steamlink-runtime`): FFmpeg 7.1 (libavcodec.so.61 is what Valve links), libepoxy (enabled in the defconfig, not selectable: Kconfig cycle with wayland), double-conversion, md4c (`package/streaming/md4c`), zstd, libkrb5 (Valve's Qt5Network links libgssapi_krb5), and the Qt 5.14.1 Wayland QPA (`/usr/lib/steamlink-runtime/qt5/{lib/libQt5WaylandClient.so.5,plugins/...}`) built from Qt sources against a qtbase 5.14.1 build SDK configured like Valve's Qt (ES2, EGL, Vulkan — the Vulkan feature changes the QPlatformIntegration vtable —, D-Bus, GLib). Valve's Qt has no Wayland plugin (on RPi OS it uses XWayland). A Qt plugin must be built for the exact Qt minor release it loads into.
- Session (`STEAMLINK_LAUNCH`, snapshot `stream_client=steamlink`, `steamlink=`, `steamlink_version/latest/job/progress/error`): `bin/shell --skip-update --fullscreen --locale <steam language>` with `QT_QPA_PLATFORM=wayland-egl`, `QT_PLUGIN_PATH` (ours first), `LD_LIBRARY_PATH` (Valve lib, Valve Qt, ours), `SDL_VIDEO_DRIVER=wayland`, `SDL_GAMECONTROLLERCONFIG` (nuubOS Gamepad, same as Moonlight), `HOME=/userdata/users/<id>/appdata/steamlink`, `TMPDIR=/tmp/steamlink`; stdout/stderr in `/run/nuubos/steamlink.log`. QUIT = SIGTERM then SIGKILL; an exit the user did not ask for (non-zero/signal) posts `stream.failed reason=steamlink`. Idle Valve UI measured ~1.3% of one core, 115 MB RSS.
- UI: Home → Applications → Steam Link (`steamlink.app`) → nuubUI page settings-view 45 (`steamlink.rs`, shares the streamd listener of `moonlight.rs`): Download (Steam Subscriber Agreement notice), progress (A cancels), Open / Update to x or Check for Updates / Remove. QM: STEAM LINK section (rows 15 Resume, 16 Quit Steam Link). Headless: `steamlink_*`, `qm_steamlink` scenes.
- Manual prototype without the service: Valve tarball extracted with symlinks resolved, then the same environment as `steamlink_session_env()` in `streamd.c`; the Qt `vnc` platform plugin bundled by Valve works as a display of last resort (RFB 3.3, no auth).
- Test on target: `nuubos-streamctl steamlink check|install|cancel|remove|launch`, `nuubos-streamctl status | grep steamlink`. Never `quit` while the user may be streaming.
- Display change during a stream (2026-10-15, user: "after Steam Link the input no longer works"; the TV had switched itself off and on): HDMI gone → labwc enables the panel → HDMI back, so the player's display changes and it recreates its SDL renderer. Left to choose, SDL3 then tried desktop OpenGL (`Couldn't create opengl renderer: Could not initialize OpenGL / GLES library`), every frame was dropped (`DroppedDecodeCorrupt`) and the session stayed frozen with the controllers captured. streamd sets `SDL_RENDER_DRIVER=opengles2`: the renderer is recreated (`Created opengles2 renderer`), but Valve's player then segfaults while reinitialising the decoder (`steamlink exited status=11`), so the user lands back on the Steam Link page with working input and has to reopen it. Reproduce without touching the TV: `echo off > /sys/class/drm/card0-HDMI-A-1/status`, wait until `wlr-randr` no longer lists HDMI-A-1 (~12 s), then `echo detect` (repeat until it is back); a short off is never seen by wlroots. KMS hotplug trace: `echo 0x4 > /sys/module/drm/parameters/debug` (set back to 0). Log: `<user>/appdata/steamlink/.local/share/Valve Corporation/SteamLink/streaming_client.log`. Moonlight not yet checked for the same case.
- Video path (found 2026-10-14 on the CubeXX): Valve's player decodes with our FFmpeg (v4l2-request, Cedrus, DRM_PRIME) and imports the frame straight via `zwp_linux_dmabuf_v1` (first layer format + object 0 modifier, crop applied) — same as Moonlight. Its Wayland output also allocates from `/dev/dma_heap/{vidbuf_cached,linux,cma,reserved}`: without dma-heaps it fails ("Failed to create dmbauf control", printed to a buffered stdout and lost) and its teardown dereferences NULL → SIGSEGV in `shell` when a stream starts. `system_heap`/`cma_heap` are modules (`=m`), loaded at boot by `S02nuubos-probe` (`reserved` = default CMA, 32 MB). Valve's own log: `$HOME/.local/share/Valve Corporation/SteamLink/streaming_client.log`. Debug a crash: `prlimit --pid $(pidof nuubos-streamd) --core=unlimited`, `core_pattern=/tmp/core.%e.%p` (USERDATA is exFAT: cores abort there), `gdb` on the host reads aarch64 cores; `llvm-objdump -d` disassembles Valve's stripped binary.
- Cedrus stride bug (kernel patch 0109, 2026-10-14): widths multiple of 16 but not 32 (720: CubeXX 720x720, RG34XX 720x480, Steam Link's 720x406) decoded the IDR fine and corrupted every predicted frame (streaks, green blocks) with `errors=0`; NV12 stride is now `ALIGN(width, 32)`. `tools/moonlight-vdec/run.sh` (with `SLICES=N` for multi-slice) qualifies it without a host; always test 720 wide, not only 640/1080p.
- First Open failing (user report 2026-10-17, every device, "could not be started", then it starts): `launch_steamlink` refused with `unavailable` while ANY Steam Link job ran, and Home sends `STEAMLINK_CHECK` (a request to Valve) on every page visit, so an Open pressed during the check failed (slow first network after a boot). Now only install/remove/rollback hold the launch; a check keeps running and its automatic update already waits for an idle session.
- Controllers seen twice (2026-10-18, RG35XX Pro, 8BitDo Ultimate 2C over Bluetooth, user: "Start does not open the game menu", "the hotkey also opens Steam's menu"): Valve's SDL3 opened the controller's `/dev/hidraw0` with its HIDAPI drivers, past inputd's evdev grab (`controller_personalization_0x2dc8_0x301b.bin` next to the `0x0000_0x0000` of our pad): the PC got Start from two controllers and the Quick Menu button (the 8BitDo's Home, `BTN_MODE` 316) as the Steam button. streamd sets `SDL_JOYSTICK_HIDAPI=0` for Steam Link, so it only sees the `nuubOS Gamepad` pads (as Moonlight). To verify on hardware: `ls -l /proc/$(pidof shell)/fd | grep hidraw` empty, Start opens the game menu once, Home only opens our Quick Menu (checked 2026-10-18: no hidraw fd). It still opened the physical evdev nodes (grabbed, silent) and announced the console's stick and the 8BitDo to the PC as extra controllers: our udev rule clears `ID_INPUT_JOYSTICK`, and SDL, finding no ID_INPUT_* class and no `ID_CLASS`, guesses from the capabilities; the rule now also sets `ID_CLASS=nuubos-physical-controller` (input.md). Verified: Valve sends only the two `nuubOS Gamepad` (`Sending HID device ... nuubOS Gamepad`).
- Still open: Steam Link's Qt UI is cut on the right at 720x720 (window ~860 px wide, also at scale 1, so not the 1.125 output scale).
## Media playback and Jellyfin (§37.25, EPIC-027/028)
- FFmpeg (defconfig) now also builds the media decoders/demuxers/parsers (h264 hevc mpeg2 mpeg4 vp8 vp9, aac mp3 flac opus vorbis ac3/eac3 alac pcm, subtitle decoders), protocols `file http tcp` (no TLS: Jellyfin over plain http only), a few filters, hwaccels h264/hevc/mpeg2/vp8/vp9 `v4l2request`, avformat/avfilter. Option changes need `ffmpeg-reconfigure`. `BR2_PACKAGE_MPV=y` (0.40, dmabuf-wayland + drm + gpu; **no PipeWire output**: `--ao=pipewire` falls back to ALSA → PipeWire ALSA plugin); libplacebo options in `external.mk` (`-Dxxhash=disabled`, else it picks the host /usr/local include).
- Redesign 2026-10-12 (explicit user request during Alpha→RC: "ripensa completamente le app di Files e Media … due app distinte", then "un media center completo deve essere"): Media is a full media center, superseding EPIC-028's "lightweight player, not a media-center database" (still no database: everything is read from folders when asked). Files is a separate two-pane commander (connectivity.md).
- Package `nuubos-media` 0.2.0. `nuubos-mediad` (`S49nuubos-mediad`, `/run/nuubos/mediad.sock`, protocol in the source header) owns the one mpv session over JSON IPC on an inherited socketpair (`--input-ipc-client=fd://3`). Two kinds: **video** = mpv fullscreen, `--hwdec=v4l2request --vo=gpu --gpu-context=wayland --wayland-app-id=nuubos-video` (the app_id exempts it from the 720-row HDMI client cap: native 1080p buffer, ui.md), on the built-in panel also `--video-align-y=-1` (letterboxed video at the top, room below free; user request 2026-10-14; output asked at start from `nuubos-displayctl hdmi`, like Home: plugging HDMI mid-video keeps the alignment until the next video; verified on the CubeXX 720x720), per-user watch-later resume in `appdata/media/watch-later` written with the file name (`--write-filename-in-watch-later-config`, read by medialib for Continue Watching), an explicit start (even 0) overrides it; **audio** = no window (`--idle=yes --force-window=no --vid=no`), mediad owns the queue (`PLAYLIST <start> <count> [shuffle]` + one `<path|url>[\t<title>]` line each, `PLAYDIR`, `QUEUE`, `JUMP`, `SHUFFLE` keeps the current track first, `REPEAT` off/all/one, `SEEKTO`, `VOLUME`), loads one track at a time (`loadfile`, titles forced with mpv's `%n%` quoting) and advances on `end-file` eof; errors skip, all broken = stop + `media.failed`. A new PLAY* while something plays replaces it (stop, then start). Snapshot adds `artist album position duration shuffle repeat volume codec rate bits queue_id`; position is published on discontinuities and extrapolated by clients (no ticking). `bits` comes from the FLAC STREAMINFO (mpv decodes 24-bit to s32). `/run/nuubos/media-playing` exists while something plays (not paused): nuubos-systemd does not idle-Sleep then (system.md).
- Video decode (found 2026-10-12: video was black): `--hwdec=drm` is not a hwdec for FFmpeg's v4l2request hwaccel → software decoding, and dmabuf-wayland cannot show software frames. mpv 0.40's drmprime interop only offered a DRM device; `patches/packages/mpv/0001` also registers a `v4l2request` device (type looked up by name) for the same DRM PRIME frames. `--vo=gpu` imports Cedrus frames without a copy (EGL dmabuf) and also shows software-decoded codecs (MPEG-4, AV1…), which dmabuf-wayland would leave black. Measured on the CubeXX: H.264 1080p30 6 Mb/s "Using hardware decoding (v4l2request)", ~8 % total CPU (dmabuf-wayland ~5 %); user confirmed the picture. The patch was applied to the existing `output/h700/build/mpv-0.40.0` tree + `mpv-rebuild` (no dirclean).
- Codecs and smoothness (GitHub #2, 2026-10-25: 1080p24 x264 2.5-5 Mb/s "very jittery"). Hardware (Cedrus, H616 = H6 variant): H.264 8-bit, HEVC Main and Main 10, MPEG-2, VP8; checked 1080p24 H.264 8-bit, HEVC 8/10-bit (`Using hardware decoding (v4l2request)`, mpv ~2 % CPU). H.264 10-bit (High 10) is a hardware limit (no such capability in the video engine): FFmpeg's hwaccel setup fails and mpv decodes in software; VP9, AV1, MPEG-4 Part 2, VC-1 are software too. Measured on the CubeXX (Sintel trailer re-encoded 1080p24 4.5 Mb/s; mpv IPC `frame-drop-count`, steady state t=6-16 s): with mpv's default scalers the VO dropped 54 frames per 10 s on hardware-decoded 8-bit and 117 on software 10-bit (the Mali-G31 could not run the default up/downscalers); `--profile=fast` (bilinear, no dither / linear-light passes) dropped 0 in both, software 10-bit at ~77 % CPU (mpv total, no audio; 40 % with audio through mediad, keeping up). `--dscale=hermite` on top dropped ~47 per 10 s on 10-bit: not used. Pure decode speed of the 10-bit clip (`--vo=null --untimed --no-audio`): 38.5 fps, 43.9 with `--vd-lavc-skiploopfilter=all` (not needed now). mediad passes `--profile=fast` to every video. Not yet checked: HDMI at 1080p (no downscale) with software 10-bit; the reporter's blue screen (not reproduced). This mpv has no Lua (`-Dlua=disabled`): measure through `--input-ipc-server` + python3.
- Blue screen at some widths (GitHub #2, RG40XX-H, 1480x1080 H.264 High 8-bit, reproduced on the CubeXX): Cedrus decodes fine, mpv's GL interop imports the NV12 frame plane by plane (`DRM_FORMAT_R8` + `GR88`) and Panfrost v7 (Mali-G31) rejects a linear R8/RG88 import whose stride is not 64-byte aligned (`panfrost: rejecting image due to unsupported offset or stride alignment`, EGL 12291 `EGL_BAD_ALLOC`, `pan_layout.c` `format_minimum_alignment`; NV12 imported whole needs only 16, which is why labwc/Moonlight never hit it). Cedrus' stride is `ALIGN(width, 32)` (kernel 0109): widths whose stride is an odd multiple of 32 failed (1440, 1476-1504, 720 -> 736), 1456/1472/1920/1280/1366 passed. Tried and dropped: (1) Cedrus stride `ALIGN(width, 64)` -> the import works but the video engine reads reference frames with the 32-aligned stride: horizontal streaks on predicted frames (like the old 720 bug); (2) Mesa accepting 16 for explicit linear R8/RG88 imports -> import ok, GPU page faults (`JOB_BUS_FAULT`, TRANSLATION_FAULT) and a black video. Fix (mediad `hwdec_fit()`): every video starts with `--hwdec=v4l2request-copy` (hardware decode, frame copied to a GPU texture, any width), and when `video-params/w` says the 32-aligned stride is a multiple of 64 mediad sets `hwdec=v4l2request` (zero copy). Starting direct and falling back flashed blue for 2-3 frames (user saw it). Measured (CubeXX, mpv IPC, steady state, `--profile=fast`): copy at 1480 and 1920 0 dropped frames, mpv ~20-23 % CPU; direct 1920 ~2-4 %; 720x720 copy ~7 %.
- Crash or garbage at some widths (GitHub #35, 2026-11-09, reproduced on the CubeXX with H.264 High 1480x1080, also with `--hwdec=no`): not the decoder. Upstream Panfrost switches a texture to linear in place after 8 complete overwrites with only an `assert` that the linear layout fits; linear rows are 64-byte aligned, tiled ones 16, so an R8 plane 1480x1080 needs 1536 x 1080 (0x195000) against 1488 x 1088 (0x18c000 in pages). `util_copy_rect` ran off the mapping at line 1056: SIGSEGV in mpv's vo thread about 8 frames in, or corruption when the BO cache had handed out a larger BO. Fixed by Mesa patch 0011 (a BO that fits, tiled if the allocation fails, descriptors re-emitted). Checked: 1480x1080 plays to the end with a clean frame, 1920x1080 unchanged. mediad's stderr goes to /dev/null: run mpv by hand for the exit status, `echo 1 > /proc/sys/kernel/print-fatal-signals` gives the registers.

## Screen casting (EPIC-029, pulled forward on user request 2026-10-13: "Implementa il casting dello schermo tramite i protocolli principali", only protocols implementable without breaking laws or copyright)
- Package `nuubos-cast` 0.1.0: `nuubos-castd` (`S49nuubos-castd`, `/run/nuubos/castd.sock`, log `/run/nuubos/castd.log`, protocol in the source header), `nuubos-castctl status|watch|discover|start ID|stop|set audio 0|1|set latency low|normal|smooth|h264 install|cancel|remove|pre-power`, `/usr/lib/nuubos/nuubos-cast-session` (one child per discovery/session, log `/run/nuubos/cast-session.log`, discovery `cast-discover.log`), `/usr/lib/nuubos/nuubos-openh264-get`, pre-power hook `58-cast` (Sleep/Restart/Power Off release the receiver first). castd idle = poll without timeout; the only timer is the bounded stop of a session.
- Protocols (one receiver list, each entry with its protocol and delay class; `rx=id\tname\tprotocol\tdelay\tmodel\tready`):
  - **Google Cast** (`_googlecast._tcp`): CASTV2 over TLS 8009 (receiver certificate not verified: device auth needs Google's roots; LAN device chosen by the user), LAUNCH of the built-in Cast Streaming app `0F5096E8` (Chrome's mirroring), OFFER/ANSWER on `urn:x-cast:com.google.cast.webrtc`, then VP8 (libvpx, realtime, CBR) + Opus 10 ms frames over Cast RTP: AES-128-CTR per frame (nonce = IV mask XOR frame id), 1449-byte payloads, RTCP SR every 500 ms, Cast feedback ACK/NACK/CST2, PLI → key frame, kickstart, in-flight budget clamp(2·RTT, 66 ms, delay/3) checked BEFORE encoding (a skipped picture never breaks the VP8 chain), simple adaptive bitrate (skips/retransmits every 2 s). Payload types 127/96 like Chrome. Wire rules from libcast/openscreen (BSD, `cast/streaming/impl`, `cast/protocol/streaming_session_protocol.md`; no code copied). delay=low, playout delay = setting Latency (low 120 / normal 250 / smooth 400 ms). Fallback when LAUNCH_ERROR / no ANSWER / refused offer: Default Media Receiver `CC1AD845` LOADs `http://<console>:<port>/nuubos.webm` (live WebM VP8+Opus, as gnome-network-displays does) → delay=high, `fallback=1`.
  - **Miracast over Infrastructure** ([MS-MICE], `_display._tcp`): TCP 7250 SOURCE_READY (UTF-16LE friendly name, RTSP port, source id), our RTSP server (7236, else any port), WFD source M1 → wait for the sink's M2 (2 s fallback) → M3 → M4 (`wfd_video_formats` CBP level 3.1, CEA 640x480p60 for screens ≤ 480 lines, else 1280x720p30 when offered; AAC if the sink offers it and audio is on) → M5 trigger SETUP → sink SETUP/PLAY → RTP PT 33, 7 TS packets per datagram (H.264 + AAC-LC 48 kHz), keep-alive GET_PARAMETER every 25 s, `wfd_idr_request` → IDR, stop = trigger TEARDOWN + STOP_PROJECTION. No HDCP, no PIN handshake. Needs Cisco's OpenH264 (below); `ready=0` until installed (Quick Menu hides it, Settings offers the download). Classic Miracast (Wi-Fi Direct) stays impossible: rtw88 has no P2P modes.
  - **DLNA/UPnP AV** (SSDP `MediaRenderer:1`, description fetched for name/model/AVTransport): SOAP Stop, SetAVTransportURI (DIDL-Lite videoItem), Play on a thread (renderers fetch while handling Play) → `http://<console>:<port>/screen.ts`, live MPEG-TS MPEG-2 video (FFmpeg mpeg2video, 6/9 Mb/s, GOP 0.5 s) + MPEG-1 Layer II 192 kb/s, close-delimited body with DLNA headers; each new GET restarts the muxer (tables + key frame). End = no client for 8 s after streaming, nothing fetched in 25 s = `unsupported`. delay=high.
  - **AirPlay**: not implemented (user asked 2026-10-13). Screen mirroring is FairPlay-protected (impossible without Apple's keys); feasible later: AirPlay 2 audio with HomeKit transient pairing (public crypto, as OwnTone/pyatv) and the screen as a live HLS `/play` URL (seconds of delay); "AirPlay" only as a compatibility word, no logos.
