# PC streaming, Steam Link, media playback, Web Mode

## Moonlight (§37.14, EPIC-025)
- Packages: `package/streaming/moonlight-embedded` (2.7.1 + nuubOS patches: Wayland/V4L2 request platform, avahi optional, low-latency ALSA, `-gamepad`/`-noquitcombo`, `-control` channel) and FFmpeg 7.1.5 (Buildroot bump `patches/buildroot/0002-ffmpeg-7.1.5-buildroot-2026.08.patch`, applied by `scripts/prepare-buildroot.sh` with the graphics patch) + Kwiboo `v4l2-request-n7.1.3` series + nuubOS 0015 (a DRM hwdevice is mapped to the V4L2 request device: Moonlight and Steam Link pass DRM) + 0016 (DRM device without a path) in `patches/packages/ffmpeg/7.1.5/` (defconfig: h264/hevc decoders + hwaccels only). Buildroot package patches must apply with fuzz 0 (`patch -F0`); a version bump leaves the old `libavcodec.so.60`/`libavutil.so.58` in `output/h700/target` until removed by hand. Design, measurements and licences: `package/streaming/README.md`. `external.mk` orders FFmpeg after udev and keeps PipeWire's FFmpeg plugin off (`-Dffmpeg=disabled`, meson keeps the last `-D`).
- Video path: Cedrus (stateless V4L2, `/dev/video0` + `/dev/media0`) → NV12 dma-buf → `zwp_linux_dmabuf_v1` subsurface composited by labwc; no CPU copy, no client GL. Qualify without a host: `tools/moonlight-vdec/run.sh 640x480 60 h264|hevc` (encodes a clip on the host, runs the real renderer on target, prints decode stats; grab the screen meanwhile).
- Service `nuubos-streamd` (package `nuubos-streaming`, `S49nuubos-streamd`, socket `/run/nuubos/streamd.sock`, log `/run/nuubos/streamd.log`, Moonlight stderr `/run/nuubos/moonlight.log`, CLI `nuubos-streamctl status|watch|discover|add ADDR|remove|refresh|pair|pair-cancel|apps|launch HOST APP|quit [close]|stats|set KEY VALUE|pre-power`). Snapshot: `state=idle|starting|streaming|exiting`, settings, `discovering`, `pairing_host/pin`, `apps_host/state`, `host=id\tname\taddress\tpaired\tonline\tsaved\tprobing`, `app=id\tname`, `end=1`. Moonlight runs as a child per operation (`status`/`pair`/`list`/`quit`/`unpair` with timeouts, `stream` with stdin control), in the active user's dir with `-keydir`; idle = poll without timeout.
- Per user: `/userdata/users/<id>/appdata/moonlight/{keys/,hosts.conf,settings.conf}` (client identity created by Moonlight on first use). Settings defaults live in `streamd.c` (`DEFAULT_*`: resolution auto = active screen capped 1080p, 60 fps, H.264, bitrate auto). Not part of Reset System Settings (per-user app data).
- Discovery: one-shot mDNS PTR query for `_nvstream._tcp.local` (legacy unicast replies) when the Moonlight page opens or on Search; no avahi.
- Session: like a game: inputd `GAMEPADS ON` connection for the stream's lifetime, Moonlight reads only `nuubOS Gamepad` devices (SDL mapping in `streamd.c` `GAMEPAD_MAPPING`, player = product id), Quick Menu button opens the QM (emulation chords are consumed and ignored), pre-power hook `55-streaming` ends the stream before Sleep/Restart/Power Off (the host app keeps running). Notifications `stream.paired|pair.failed|failed reason=unreachable|unpaired|app|start|connection`.
- UI: Home → Applications → Moonlight (`/usr/share/nuubos/applications/moonlight.app`, ID `moonlight` handled by `moonlight.rs`): application page (AppPage, `apppage.rs`) for settings-view 40 PCs / 41 PC (pairing PIN or applications); 42 Stream Settings = full-screen app shell (ui.md), keyboard purpose 10 adds a PC by address. Home input and Home Music follow `moonlight::STREAM_RUNNING` like `GAME_RUNNING`. Quick Menu over a stream: STREAM section (rows 15 Resume, 16 Quit Stream, 17 Quit and Close Application with second press) and statistics sampled once when the menu opens (`STATS`). Headless: `tools/ui-shot/run.sh` renders `moonlight_*` and `qm_stream*` scenes.
- Pairing: `PAIR` shows a 4-digit PIN in nuubUI; the user enters it in Sunshine's web UI (PIN page) or GeForce Experience. Never run scripted `launch`/`quit` while the user may be streaming: check `nuubos-streamctl status` is idle.
## Steam Link (§37.15, EPIC-026)
- Valve's proprietary app, never in the image. `nuubos-streamd` downloads it on request with `/usr/lib/nuubos/nuubos-steamlink-get` (libcurl/zlib, `check | install <root> | remove <root>`, `@progress/@latest/@done/@error` lines): build pointer `https://media.steampowered.com/steamlink/rpi/trixie/arm64/public_build.txt`, streamed gzip+tar extraction into `/userdata/steamlink/.staging` (exFAT: symlinks/hardlinks become copies), swapped to `/userdata/steamlink/app`. Target BusyBox `tar` has no `-z` and cannot create symlinks on USERDATA. Requires `ca-certificates` (added) for TLS.
- Runtime in the image (`package/streaming/steamlink-runtime`): FFmpeg 7.1 (libavcodec.so.61 is what Valve links), libepoxy (enabled in the defconfig, not selectable: Kconfig cycle with wayland), double-conversion, md4c (`package/streaming/md4c`), zstd, libkrb5 (Valve's Qt5Network links libgssapi_krb5), and the Qt 5.14.1 Wayland QPA (`/usr/lib/steamlink-runtime/qt5/{lib/libQt5WaylandClient.so.5,plugins/...}`) built from Qt sources against a qtbase 5.14.1 build SDK configured like Valve's Qt (ES2, EGL, Vulkan — the Vulkan feature changes the QPlatformIntegration vtable —, D-Bus, GLib). Valve's Qt has no Wayland plugin (on RPi OS it uses XWayland). A Qt plugin must be built for the exact Qt minor release it loads into.
- Session (`STEAMLINK_LAUNCH`, snapshot `stream_client=steamlink`, `steamlink=`, `steamlink_version/latest/job/progress/error`): `bin/shell --skip-update --fullscreen --locale <steam language>` with `QT_QPA_PLATFORM=wayland-egl`, `QT_PLUGIN_PATH` (ours first), `LD_LIBRARY_PATH` (Valve lib, Valve Qt, ours), `SDL_VIDEO_DRIVER=wayland`, `SDL_GAMECONTROLLERCONFIG` (nuubOS Gamepad, same as Moonlight), `HOME=/userdata/users/<id>/appdata/steamlink`, `TMPDIR=/tmp/steamlink`; stdout/stderr in `/run/nuubos/steamlink.log`. QUIT = SIGTERM then SIGKILL; an exit the user did not ask for (non-zero/signal) posts `stream.failed reason=steamlink`. Idle Valve UI measured ~1.3% of one core, 115 MB RSS.
- UI: Home → Applications → Steam Link (`steamlink.app`) → nuubUI page settings-view 45 (`steamlink.rs`, shares the streamd listener of `moonlight.rs`): Download (Steam Subscriber Agreement notice), progress (A cancels), Open / Update to x or Check for Updates / Remove. QM: STEAM LINK section (rows 15 Resume, 16 Quit Steam Link). Headless: `steamlink_*`, `qm_steamlink` scenes.
- Manual prototype without the service: Valve tarball extracted with symlinks resolved, then the same environment as `steamlink_session_env()` in `streamd.c`; the Qt `vnc` platform plugin bundled by Valve works as a display of last resort (RFB 3.3, no auth).
- Test on target: `nuubos-streamctl steamlink check|install|cancel|remove|launch`, `nuubos-streamctl status | grep steamlink`. Never `quit` while the user may be streaming.
## Media playback and Jellyfin (§37.25, EPIC-027/028)
- FFmpeg (defconfig) now also builds the media decoders/demuxers/parsers (h264 hevc mpeg2 mpeg4 vp8 vp9, aac mp3 flac opus vorbis ac3/eac3 alac pcm, subtitle decoders), protocols `file http tcp` (no TLS: Jellyfin over plain http only), a few filters, hwaccels h264/hevc/mpeg2/vp8/vp9 `v4l2request`, avformat/avfilter. Option changes need `ffmpeg-reconfigure`. `BR2_PACKAGE_MPV=y` (0.40, dmabuf-wayland + drm + pipewire); libplacebo options in `external.mk` (`-Dxxhash=disabled`, else it picks the host /usr/local include).
- Package `nuubos-media`: `nuubos-mediad` (`S49nuubos-mediad`, `/run/nuubos/mediad.sock`, protocol in the source header) owns the one mpv session (`--hwdec=drm --vo=dmabuf-wayland,gpu --ao=pipewire,alsa`, JSON IPC over an inherited socketpair `--input-ipc-client=fd://3`, per-user watch-later resume in `appdata/media/watch-later`); `nuubos-playerctl`; `nuubos-jellyfinctl` (per-user token in `/state/users/<id>/secrets/jellyfin.conf`, direct play only, progress reported on stop); pre-power hook `56-media`; `media.failed` notification. Host test `python3 package/nuubos/nuubos-media/tests/media.py`.
- UI: Home → Applications → Media (`media.app`, XMB Monochrome `movies.png`, CC BY 4.0) → `mediaui.rs` (settings-view 65, keyboard purposes 22–24). While playing, `route_input_action` sends controller actions to the player (play/pause, seek, next/prev, subtitles, audio track, stop); Home Music stops like for a game.
- Not hardware-qualified: Cedrus decode through mpv `--hwdec=drm`, dmabuf-wayland presentation, A/V sync, Jellyfin against a real server.
## Web Mode (§37.27, EPIC-030) — parked
- **Parked** (user decision 2026-10-07): code, tests, strings and Quick Menu/Home/inputd support stay in the tree but `BR2_PACKAGE_NUUBOS_WEB` is off, so no WebKit/Cog in the image and no Web app (no `web.app`). Resume after the RC + Linux 7.3 + deep sleep + casting + Spotify Connect. Not yet built end to end: WPE WebKit was at ~1800/8300 when stopped; harfbuzz was rebuilt without ICU. Planned addition: WebKit content blocker (Cog `--content-filter`) with EasyList/EasyPrivacy converted at build time + optional user-triggered list update; Cog recompiles filters at every start, needs a patch to reuse the compiled store.

- Engine decision (open decision #11): WPE WebKit 2.50.5 + Cog 0.18.5 (Buildroot packages; Wayland `wl` platform, GLES/Skia, WebKit bubblewrap sandbox for web content and network processes, GStreamer multimedia with `v4l2codecs` for Cedrus). Licences: WPE WebKit LGPL-2.1+/BSD, Cog MIT, GStreamer LGPL, bubblewrap/xdg-dbus-proxy LGPL. NetSurf has no JavaScript, WebKitGTK needs GTK, Chromium is not in Buildroot. Selected by package `nuubos-web` (`Config.in` selects WPEWEBKIT, _SANDBOX, _MULTIMEDIA, COG, COG_PLATFORM_FDO, COG_USE_SYSTEM_DBUS, gst v4l2codecs/GL); defconfig sets `BR2_PACKAGE_COG_PROGRAMS_HOME_URI=""`; `external.mk` sets `-Dcog_dbus_system_owner=root` (an empty owner installs an invalid D-Bus policy).
- Build quirks: WPE WebKit takes ~2 h with `BR2_JLEVEL=6` (8 jobs risk OOM on 15 GB). harfbuzz must be built with ICU (`harfbuzz-dirclean` when ICU was enabled after it). `patches/packages/wpewebkit/0001` quotes variables in `_WEBKIT_TARGET_LINK_FRAMEWORK` (CMake 4.4 rejects `NOT IN_LIST` with an empty expansion). `patches/packages/cog/0001` adds remote actions `zoom-in/zoom-out/zoom-reset` (+ cogctl commands; Ctrl+= depends on the keyboard layout) and prints `@nuubos uri=|title=|zoom=` lines on stdout.
- Service `nuubos-webd` (package `nuubos-web`, `S49nuubos-webd`, socket `/run/nuubos/webd.sock`, log `/run/nuubos/webd.log`, Cog stderr `/run/nuubos/cog.log`, CLI `nuubos-webctl status|watch|open ADDR|back|forward|reload|zoom-in|zoom-out|zoom-reset|quit|bookmark-add [URL [TITLE]]|bookmark-remove URL|history-clear|clear-data|pre-power ACTION`). One Cog session: `cog --platform=wl --webprocess-failure=error-page --cookie-jar=sqlite --cookie-store=no-third-party --web-mem-limit=450 --enable-spatial-navigation=true`, env `COG_PLATFORM_WL_VIEW_FULLSCREEN=1`, `LANGUAGE=<user language>`, `DBUS_SESSION_BUS_ADDRESS=disabled:` (GApplication runs non-unique; control on the system bus with `cogctl --system`). Addresses: host names get `https://`, anything with spaces/without a dot is a DuckDuckGo search (`docs/privacy.md`). Per user: `/userdata/users/<id>/appdata/web/{bookmarks.tsv,history.tsv,data/}` (XDG_DATA_HOME), cache `/userdata/cache/web/<id>` (removed by Reset User Profile and user deletion). Pre-power hook `57-web`: Sleep keeps the page, Restart/Power Off quit Cog. Notifications `web.failed reason=start|crash`, `web.bookmark.added`. Host test `python3 package/nuubos/nuubos-web/tests/webd.py`.
- Input: webd holds an inputd `WEB ON` connection for the session (like `GAMEPADS ON`; controllers grabbed): one uinput "nuubOS Web Input" keyboard + pointer (inputd ignores it as a source). Mapping follows the user's controls: D-pad = arrows (spatial navigation), confirm = Enter, back = Alt+Left, north = left click, west = Escape, L1/R1 = Page Up/Down, Start/Select = Tab/Shift+Tab, left stick = pointer, right stick = hi-res wheel (16 ms timer only while a stick is deflected), L2/R2/L3 = `HOTKEY zoom_out|zoom_in|zoom_reset` to webd. Only layout-neutral keys are injected; `web=` in inputd STATUS.
- Text entry: the Quick Menu registers `zwp_input_method_v2` (labwc/wlroots; bindings generated by `wayland-scanner` from `nuubos-quick-menu/src/protocols/input-method-unstable-v2.xml`, enum refs to text-input-v3 stripped) on its own connection/thread (`src/ime.rs`). When a field of the page is focused (Cog text-input-v3) it shows a full-width bottom keyboard sheet (`SurfaceKind::Keyboard`, `surface-mode` 2, 236 logical px) and takes the controller (inputd MENU OPEN); keys are committed as UTF-8 (`commit_string`, ⌫ = `delete_surrounding_text`), so the keyboard layout setting only picks the key arrangement. Back/Done closes it (the field keeps focus; Quick Menu → WEB → Keyboard reopens it); M/power open the Quick Menu instead.
- UI: Home → Applications → Web (`web.app`, icon XMB Monochrome `menu_room.png`, CC BY 4.0) → `webui.rs` (settings-view 67, full-screen app shell with generic rows, ui.md): Enter Address (keyboard purpose 25), Bookmarks (north face = Remove, armed; `settings-north-hint` shows the hint), History, Clear History, Clear Browsing Data (armed). Home input and Home Music follow `webui::RUNNING`. Quick Menu WEB section rows 20 Resume, 27 Keyboard, 21 Go Back, 22 Go Forward, 23 Reload, 24 Zoom (←/→, confirm = 100%), 25 Add Bookmark, 26 Quit Web; power key opens the Quick Menu over the browser. Headless scenes `web`, `web_bookmarks`, `qm_web`, `qm_keyboard`.
## Steam Link updates and Moonlight settings (2026-10-10)
- Steam Link: `nuubos-steamlink-get install` keeps the replaced build as `/userdata/steamlink/previous`; `rollback <root>` swaps app/previous (twice = forward again). streamd: `STEAMLINK_ROLLBACK`, `STEAMLINK_AUTO_UPDATE\t0|1` (`/userdata/steamlink/nuubos.conf`, default on), snapshot `steamlink_previous=`, `steamlink_auto_update=`, job `rolling-back`. Automatic Updates: when a check (the page asks one on open) finds a newer build and no session runs, it installs; an installed update that exits with an error (not a user quit) within 30 s of its first start is rolled back automatically. Page actions: Open, Update/Check, Automatic Updates (toggle pill), Restore Version x (when kept), Remove.
- Moonlight is built into the image (moonlight-embedded with nuubOS patches): it updates with the system (OTA) and has the OTA rollback, no separate self-update.
- Moonlight Stream Settings (view 42) like the Moonlight app: VIDEO (Resolution, Frame Rate, Bitrate with left/right steps 0/5…150 Mbps and a slider, Video Codec) | AUDIO (Audio Channels stereo/5.1/7.1 → `-surround`, Play Audio on the PC → `-localaudio`) | PC (Optimize Game Settings, default on, off → `-nosops`; Quit the App on the PC After Streaming → `-quitappafter`). Per user in streamd `settings.conf`.
- Adaptive bitrate: moonlight-embedded/moonlight-common-c do not lower the bitrate on their own; loss is handled by reference-frame invalidation/IDR requests and the host's encoder. As far as known (not verified in the Sunshine sources, 2026-10-10), Sunshine keeps the requested bitrate (no dynamic adaptation); the Bitrate setting is the cap to lower on a weak network.
