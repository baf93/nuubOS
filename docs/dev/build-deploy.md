# Build, deploy, target access

Rules: CLAUDE.md "Build". History: the Dockerized Platform v0.5 build produced rootfs, boot/state images and the universal H700 image; Linux 7.2.8 also completed a full Dockerized build with the H700 patchset applying.

## Targeted build (§37.1)
```sh
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/workspace/.docker-home \
  -e BR2_DL_DIR=/workspace/dl -e BR2_CCACHE_DIR=/workspace/.cache/nuubos/buildroot-ccache \
  -v "$PWD:/workspace" -w /workspace nuubos-dev:0.5 \
  ./scripts/compile.sh <pkg>-rebuild [<pkg>-rebuild ...]
```

`compile.sh` forwards its arguments to Buildroot `make` and restores Buildroot pristine on exit. Gotcha: when several `-rebuild` targets go in one invocation, a package that is also a dependency of an earlier one (e.g. `nuubos-input`) is already "made" before its own clean runs and is silently NOT rebuilt — check for its `>>> <pkg> Building` line, or rebuild it alone. Packages touched most often: `nuubui-home`, `nuubos-quick-menu`, `nuubos-localization`, `nuubos-audio`, `nuubos-system`. Results land in `output/h700/target/`. A Rust UI rebuild takes ~40 s.

## OpenSSL 4 (2026-10-28)
- Fresh builds of Qt 6.11.1 need `patches/packages/qt6base/0001-openssl-4-opaque-asn1-strings.patch`: OpenSSL 4 makes ASN.1 string internals opaque. The patch uses Qt's existing dynamically resolved accessors for certificate key identifiers, IP addresses and serial numbers. TLS and scraper behavior still need target qualification.
- A fresh Buildroot Cargo cache may be empty for local-source packages: their offline builds do not fetch dependencies automatically. After the Buildroot host toolchain is available, run `CARGO_HOME=/workspace/dl/br-cargo-home cargo fetch --locked` inside the container from `package/nuubos/nuubos-quick-menu/src` and `package/nuubos/nuubos-remote/src`, with `/workspace/output/h700/host/bin` first in `PATH`, then resume the build.
- U-Boot 2026.07 host tools need `patches/u-boot/platform/h700/0009-openssl-4-no-engine.patch`: OpenSSL 4 removed ENGINE. PEM keys remain supported; requests to use an ENGINE fail explicitly. Boot and signing still need target qualification.
- Buildroot's CA bundle hooks use `openssl rehash` via `patches/buildroot/0004-ca-certificates-openssl-rehash.patch`, since OpenSSL 4 no longer supplies `c_rehash`.
- libopenssl 4.0.3 through `patches/buildroot/0003-libopenssl-4.0.3-buildroot-2026.08.patch` (version + hash; Buildroot 2026.08 ships 3.6.4, end of life). Soname `libssl.so.4`/`libcrypto.so.4`: every package linking OpenSSL must be rebuilt; find them with `readelf -d` over `output/h700/target` (NEEDED `libssl.so.N`/`libcrypto.so.N`), not from the `.mk` dependencies. The old `.so.3` files stay in target/staging after the bump and hide forgotten packages: removed by hand (user permission) so a stale link fails. Then check unresolved OpenSSL symbols too (`nm -D --undefined-only` against the exports of the two libraries): Python extension modules link with undefined symbols allowed, so a removed function only fails at import time.
- API breaks met: `ASN1_STRING` opaque (use `ASN1_STRING_length`/`ASN1_STRING_get0_data`), `X509_get_subject_name()` returns const (build an `X509_NAME` and `X509_set_subject_name` + `X509_set_issuer_name`: nuubos-web-cert, moonlight patch 0007), fixed-version methods (`TLSv1_method` & co.) removed without `OPENSSL_NO_*_METHOD` macros (CPython `_ssl`: `patches/packages/python3/0001`), engines gone. libkrb5 (only for Steam Link's Qt GSSAPI) is built with `--disable-pkinit --without-tls-impl` (same patch 0003): PKINIT and k5tls do not build with OpenSSL 4. Steam Link (Valve build) and Tailscale (Go) do not use the system OpenSSL.
- Rebuild gotchas: `<pkg>-reconfigure` does not recompile when configure regenerates an identical `config.h` and the package is built with `--disable-dependency-tracking` (libcurl, openssh, libkrb5 kept their 3.x objects, or relinked old objects against 4.0): `touch` the package's `.c` files, then `<pkg>-rebuild`, and check the object times. krb5 enters a plugin directory whenever a generated `Makefile` is there, so a plugin turned off after a build keeps building until that stale `Makefile` goes.
- Bulk deploy with tar: pack only files (no directory entries) and as root (`tar --owner=0 --group=0`, or `chown root:root` after): extracting a host tar with `./usr` entries made `/`, `/usr` and `/usr/lib` owned by uid 1000 on the target (2026-10-28, fixed by hand).

## Release: licenses and sources (GPL/LGPL/MPL/BSD/MIT/CC obligations, 2026-10-11)
Every published image must ship with the matching `legal-info`: after the image build run `./scripts/compile.sh legal-info` (same Docker command) and publish `output/h700/legal-info/` (`manifest.csv`, `licenses/`, `sources/`, `buildroot.config`; ~3 GB) next to the image, plus `licenses/` of this repo and the repo state (patches) of the release. legal-info copies the patches listed in each build dir's `.applied_patches_list`: a patch deleted from `patches/` after that package was built aborts it (2026-10-16: `linux-headers-7.2.8` still listed `patches/linux/h700/0012-rtw88-...` removed on 2026-10-15; the headers really were built with it, so it was restored from git (`git show <deleting commit>~1:<path>`) only for the legal-info run and deleted again; a clean build no longer has it). Every package needs `<PKG>_LICENSE` and an existing `<PKG>_LICENSE_FILES`: a wrong path aborts legal-info (fixed for libretro-stella2014: `stella/license.txt`). Non-commercial cores (FBNeo, Genesis Plus GX, MAME 2003-Plus, PicoDrive, Snes9x, Mu CC-BY-NC): nuubOS must stay free and non-commercial (no sale, no preinstall on sold hardware).

## nuubOS license and the pre-release gaps (user decision 2026-10-16)
- nuubOS is licensed **GPL-3.0-or-later** since 2026-11-10, 1.0.0-rc.5 (user decision: SourceForge becomes the download and OTA backend and its terms require an Open Source Definition license; the bundled noncommercial cores and the name/logo rule in LICENSING.md already keep the full image from being sold; contributions are covered by the contribution terms of 2026-10-16): root `LICENSE` and every `package/nuubos/*/src/LICENSE` = a short notice + the FSF GPL-3.0 text, `<PKG>_LICENSE = GPL-3.0+`, SPDX `GPL-3.0-or-later`. Before: MIT until 2026-10-16, PolyForm Noncommercial 1.0.0 until 1.0.0-rc.4 (copies keep those terms). Thiago A. Silva's RC3 contribution (emud.c, inputd.c, translations, RetroArch 0006) came after the contribution terms of 2026-10-16 (docs/technical/contributing.md: the maintainer may offer contributions under other terms), so it moved too; a courtesy note to him when GitHub is back. Some bundled cores stay noncommercial under their own terms (LICENSING.md).
- Exception: nuubui-home and nuubos-quick-menu are **GPL-3.0-only**. They link Slint, whose free license (Royalty-free 2.0) excludes embedded systems; the paid Slint Software License needs a royalty per device; so Slint is used under GPL-3.0 and the GPL forbids adding a noncommercial restriction. Any new program linking Slint (or another GPL-only library) must be GPL-3.0 too. C programs link only permissive/LGPL libraries (FFmpeg without GPL parts, libsmb2/ALSA/mpg123 LGPL dynamic, D-Bus AFL), checked 2026-10-16 with `readelf -d`: keep it that way.
- Third-party notices: `scripts/third-party-notices.py` (hooks `NUUBOS_CARGO_NOTICES` / `NUUBOS_GO_NOTICES` in `external.mk`, used by nuubui-home, nuubos-quick-menu, nuubos-remote, syncthing) writes `/usr/share/licenses/<pkg>/THIRD-PARTY-NOTICES.txt` at every build: crates reached through normal dependencies for the aarch64 target (`cargo metadata --filter-platform`), Go modules from `vendor/modules.txt`, each with its declared license and its license/notice files (identical texts once). It fails the build when a component has no licensing information. Measured: nuubui-home 379 crates, nuubos-remote 87, Syncthing 87 modules.
- `external.mk` overrides the legal-info metadata of DejaVu (Bitstream Vera + public domain changes + Arev) and linux-firmware (only rtw88/rtl_bt, redistributable binary under `LICENCE.rtlwifi_firmware.txt`).
- VICE: the Commodore ROMs are not redistributable; removed from the build and the legal-info source archive (package/libretro/README.md), users supply them as BIOS files.
- Panel firmware: generated at build time from the JSON presets in `board/nuubos/platform/h700/panel-firmware/presets` by `scripts/generate-panel-firmware.py` (no copied blob ships).

## Development target and deploy (§37.2) — ALWAYS deploy after a change when no flash is needed
- Target: RG40XX-V at `root@192.168.5.43` (user, 2026-10-08), `scp`/SFTP available. SSH is password-only since 2026-10-07 (device credential, Settings → Connectivity → SERVICES → Password; keys are not accepted): the user supplies it. Non-interactive use from the host without sshpass: an askpass script that prints it, `SSH_ASKPASS=<script> SSH_ASKPASS_REQUIRE=force ssh ...` (keep the script outside the repo, e.g. the session scratchpad).
- The target runs the current working tree (all services incl. users/regional/localization/PipeWire).
- `tools/deploy-target.sh` and `tools/grab-target.sh` call ssh/scp with `BatchMode=yes` (keys only) and default to `.36` (pass `-H root@192.168.5.43`): with the password-only target put ssh/scp wrappers first in PATH that prepend `-o BatchMode=no` (the first `-o` wins) and set the askpass env; grab takes `-H root@IP`. The target IP is DHCP-assigned and may change (2026-10-08: `.43`, 2026-10-11: `.39`).
- Use `tools/deploy-target.sh [-s S50nuubos-ui] [-s S43nuubos-audiod ...] /abs/path ...`: stages files from `output/h700/target`, backs up originals in `/tmp/nuubos-deploy/backup`, verifies md5, stops the given init scripts, installs, restarts them (reverse order).
- Screenshots of the real screen: `tools/grab-target.sh <name>` (drm-grab drops DRM master right after opening the card since 2026-10-10: a grab while labwc started used to steal master and leave labwc on a black screen, "Could not make device fd drm master"; for frame sequences start grabbing only once `pidof nuubui-home` succeeds). Restarting the UI on the target: `S50nuubos-ui stop`, then `killall labwc` (stop does not always end it), then `start` → `output/grab/<name>-crtcN.png` (reads the scanout framebuffer via DRM GETFB2; dev tool in /tmp only). There is no input injection; ask the user to navigate.
- HDMI density: `nuubos-wl-output-apply` sets the output scale so the UI sees ~720 logical lines (1080p → 1.5, 1440p → 2, 2160p → 3; user found 2.0 at 1080p too large). UI buffers are capped at 720 rows on HDMI (`NUUBOS_CLIENT_MAX_LINES`, wlroots patch 0001 + labwc 0003, ui.md) and scaled up by the display engine. Mesa patches: apply to `output/h700/build/mesa3d-25.0.6`, `compile.sh mesa3d-rebuild`, deploy `/usr/lib/libgallium-25.0.6.so`. wlroots patches: apply to `output/h700/build/wlroots-0.20.2` (already-patched tree), `compile.sh wlroots-rebuild`, deploy `/usr/lib/libwlroots-0.20.so` and restart `S50nuubos-ui`. Home (winit) handles fractional scale natively; the Quick Menu uses wp_fractional_scale_v1 + wp_viewporter and renders at physical resolution.
- Output policy (HDMI only, the sink's preferred mode capped at 1080 lines at the preferred refresh, e.g. a 4K60 TV gets 1080p60 and upscales it (user request 2026-10-08: UI at 1080p; at 2160p the GPU also hit job timeouts); internal panel otherwise; games keep this mode and render a smaller buffer the display engine scales (emulation.md); within the cap, square-pixel modes win over anamorphic CEA 720x480/720x576; `nuubos-wl-output-apply --hdmi-mode OUTPUT` prints the chosen `WxH@Hz`, also used by the watcher's topology check; target awk is BusyBox: no `^`) lives in `nuubos-wl-output-apply`; `nuubos-wl-output-watch` (labwc autostart) applies it at session start only if HDMI is connected and the topology does not already match, then on DRM hotplug. Rootfs-overlay scripts are deployed by copying the file from `board/nuubos/common/rootfs-overlay/` (no package rebuild).
- After restarting `S43nuubos-audiod`, Home Music only restarts when the UI requests it again: restart `S50nuubos-ui` too.
- UI binaries (`/usr/bin/nuubui-home`, `/usr/bin/nuubos-quick-menu`) and `/usr/share/nuubos/i18n/*.lang`: `/etc/init.d/S50nuubos-ui stop`, install, `/etc/init.d/S50nuubos-ui start`, check `/run/nuubos/ui-ready`.
- Services: use their own `/etc/init.d/S??nuubos-*` stop/start.
- `nuubos-syncd`: same trap with `-s S49nuubos-syncd` (2026-10-28): stop is an async SIGTERM, syncd takes seconds to stop Syncthing, and the old process's exit unlinks the new one's `syncd.sock` (`nuubos-syncctl status` -> `ERR service`). Install without `-s`, then `S49nuubos-syncd stop`, wait until `pidof nuubos-syncd` is empty, `start`.
- `nuubos-inputd`: never deploy it with `-s S47nuubos-inputd` (stop is an async SIGTERM, the immediate start sees the still-alive pid and does nothing, leaving no inputd = no controls). Install the file with no `-s`, then run `/etc/init.d/S47nuubos-inputd restart` (flock handoff). inputd ignores SIGPIPE since 2026-10-08: before, a UI restart/crash could kill it on the next write to the closed Home socket.
- NEVER `cat`/`grep` over `/run/nuubos/*`: `/run/nuubos/ui-control` is a FIFO and the command blocks forever (and steals lifecycle messages).
- Target has `wlr-randr`, `wpctl`, `pw-cli`, `pw-dump`; no `grim`, no `pkill` (use `kill`/`killall`). Wayland env: `XDG_RUNTIME_DIR=/run/nuubos/wayland-runtime WAYLAND_DISPLAY=wayland-0`.
- Logs: `/run/nuubos/*.log` (regular files), `labwc.log` holds UI client stderr.
- Bulk deploy (many packages): compare md5 of the target rootfs with `output/h700/target`, stripping ELFs with the toolchain `strip --remove-section=.comment --remove-section=.note` first (target files are unstripped until finalize). `output/h700/target` is pre-finalize: never copy its `etc/passwd|group|shadow|timezone`, `bin/busybox`, or files the rootfs overlay owns (take those from `board/nuubos/*/rootfs-overlay`); `/etc/os-release` is written by post-build. Missing `.so.N` symlinks must be shipped too. Target BusyBox `tar` has no `-z`: `gunzip -c x.tgz | tar xf - -C /`. Back up replaced files to `/userdata` first (done 2026-10-07: `/userdata/nuubos-deploy-backup-20261007.tgz`).
- Moonlight on the target: deploy `/usr/bin/moonlight` together with `/usr/lib/libmoonlight-common.so.2.7.1` and `libgamestream.so.2.7.1` (patch 0006 changed shared structs: a binary-only deploy on 2026-10-13 made every `moonlight status/stream` segfault, PCs shown offline). Use `/run/nuubos/wayland-runtime` + `wayland-0` for `wlr-randr` over SSH.
- Kernel: `/boot/Image` lives on the running system slot (p1 or p5, `nuubos.slot=` in `/proc/cmdline`; deploys go to the running slot, an OTA to the other one). Kernel-only change: add the patch under `patches/linux/h700/`, apply it to `output/h700/build/linux-<version>` (already-patched tree; 7.3 since 2026-10-20), `compile.sh linux-rebuild`, scp `output/h700/images/Image` to `/boot/Image` (keep a backup), reboot.
- Kernel version bumps leave the old `lib/modules/<release>` in `output/h700/target`: `post-build.sh` keeps only the release of the configured kernel (`$BUILD_DIR/linux-<version>/include/config/kernel.release`), so images never ship stale modules (2026-10-20: 7.2.8 and 7.3.0-rc7, 24 MB).
- Target has no `depmod`: after adding a module, run `output/h700/host/sbin/depmod -b output/h700/target <uname -r>` (7.3.0) and deploy `modules.*` with the `.ko`. Kernel version bump: also deploy the whole `lib/modules/<release>` (depmod first) and every DTB, back up `/boot/Image` + DTBs first.
- New crates (MIT/Apache, Slint femtovg same terms as Slint): `femtovg`, `fnv`, `gbm`, `gbm-sys`, `i-slint-renderer-femtovg`; fetch into the Buildroot cargo cache with `cargo fetch` run in the container with `CARGO_HOME=/workspace/dl/br-cargo-home` and `PATH=/workspace/output/h700/host/bin:...` (local cargo packages build `--offline --locked` from that cache).
- Buildroot package patches must apply with fuzz 0; FFmpeg bump leftovers: streaming-media.md §37.14.
- Hand-edited patch hunk header miscounted (2026-10-22, first from-scratch build on a fresh checkout): `libretro/retroarch/0006-nuubos-overscan-crop-for-tv-systems.patch` hunk 1 said `@@ -2410,6 +2410,26 @@` but the body has 27 new lines (6 context + 21 added, including a blank `+` line before the following doc comment); `patch` swallowed the next context line as part of hunk 1 and then choked on hunk 2's real header ("malformed patch at line 43"). Same class of bug as the kernel 1708 quirk's zero-context hunk (input.md). Fixed by correcting the count to `+2410,27`; verified with `patch -p1 --dry-run` against the extracted `output/h700/build/retroarch-1.22.2` tree. Worth a `patch --dry-run` sanity check on any hand-edited hunk before it reaches a real build.

## SSH / SFTP (§29)
Slow SSH on Linux 7.2.8 was reverse DNS, not a kernel regression: the development host mapping on the target fixed it. Don't reopen as a kernel bug without new evidence. The target ships an SFTP server so scp/SFTP work natively (no stdin-over-SSH workarounds); check repo state before reimplementing.
- `legal-info` copies every patch named in each package's `.applied_patches_list`: a patch removed from the repo but still listed (rtw88 `0012`, dropped 2026-10-15 and reverted by hand in `linux-7.3-rc7` and `linux-headers-7.2.8`) fails it with `cannot stat`. Fixed 2026-10-18 by deleting that line from both lists; when a patch is dropped, rebuild the package from a fresh extract or remove its line too.
