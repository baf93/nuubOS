# Quick Menu and notifications/OSD

## Quick Menu (§17)
System-wide contextual overlay opened with `M`, above Home, Settings, applications and games/fullscreen clients: the compositor must support overlay/layer rendering and OSD/notifications over fullscreen clients and correct focus/input routing, without product logic in the compositor. Context-sensitive: the most useful actions for the current context.
- Audio (§17.1): ONE `Audio` row (no separate Output/Master/System Sounds/Home Music rows). Left/right = master volume of the selected physical output ±1%; confirm = dropdown of available outputs incl. Automatic where the Product Audio contract supports it; changing output does not close the QM; routing follows Product Audio policy. System Sounds/Home Music/Application volumes stay in Settings.
- Performance Profile (§17.2) through the same system service as Settings.
- Header (user request 2026-10-08): title "Menu" (string 187), the clock centred (`clock-label` = statusd `TIME`, read with the battery from `statusd.state`), battery on the right; the glyph is `Theme.warning` while the effective profile is Battery Saver (`battery-saver`, set by `refresh_system_profile`), as in Home.
- Restart and Power Off (rows 1, 2) need a second press (user request 2026-10-08): the first arms the row (`game-confirm-index`, error roles + "Press again to confirm"), moving or closing the menu disarms it. Sleep stays single-press (committed on release).
- Switch User (§17.3) contextually (Home/Settings), real user/session mechanism.
- Power OSD (user request 2026-10-08): the Quick Menu process owns it in EVERY context (Home, Settings, safe mode, games, streams, Web); Home ignores the power key and has no copy. Same design as the old Home dialog (`PowerChoice`, strings 188-191/58): Sleep on top, Restart | Power Off below with a second press (`power-osd-confirm`). Opening maps the full overlay surface with the side sheet hidden (`menu-panel-visible` false from the first frame) and pauses a game; power or Back closes it, the Quick Menu button closes it too. Sleep commits on the confirm release only if the press was seen on the OSD; Restart/Power Off share `end_session()` with SYSTEM rows 1/2. ui-shot scenes `power_menu`, `power_armed` (QM).
- Over a game the GAME section comes first (§18.1, emulation.md); STREAM / STEAM LINK / WEB sections: streaming-media.md. QM technical notes: ui.md §37.3.

## Notifications / OSD (§19)
Global notifications/OSD above applications and fullscreen games: volume, emulation hotkey feedback, save/load state, save slot, fast-forward, other system status. Product semantics stay in services/UI, not in the compositor.

## Notifications implementation (§37.7, EPIC-006)
- Router `nuubos-notifyd` (package `nuubos-notify`, `S40nuubos-notifyd`, socket `/run/nuubos/notifyd.sock`, log `/run/nuubos/notifyd.log`): validates, drops identical messages within 3 s, fans out to subscribers, replays running Live Notifications on `SUBSCRIBE`. No history.
- Producers include the staging header `<nuubos/notify.h>` (add `nuubos-notify` to the package DEPENDENCIES + `select BR2_PACKAGE_NUUBOS_NOTIFY`). Messages are typed events with raw percent-encoded values (`POST|UPDATE|DISMISS id=… event=… key=value`); the event list lives in `notify.h`. Producers never send display text.
- Owners: audiod `music.track` (ID3v2.2/2.3/2.4/ID3v1 title/artist, file name fallback; only on a newly chosen track); controllersd `controller.connected/disconnected` (non-built-in, diff on `/dev/input` rescans; HID battery from Device-scope `power_supply` uevents matched by sysfs parent; a late battery UPDATEs the connect toast for 15 s; Bluetooth controllers (address from the HID uniq) take the level from `org.bluez.Battery1` — Get on appearance + PropertiesChanged/InterfacesAdded — which wins over the kernel value, and the kernel HID battery of uhid (BLE/HOGP) devices is ignored because it is synthetic and reads 0% (8BitDo Ultimate 2C); `accessory.battery.low` ≤15%, re-armed >20%); bluetoothd `headphones.*` for Audio-kind devices + `Battery1` low battery for non-controllers; statusd `battery.low/critical/charging/full` (15/5%, re-arm 20%, once per charge session); systemd `battery.saver` (automatic switch only) and `storage.job` Live Notification; wifid `wifi.connected/lost` (lost = association gone without a user action, posted only if not reconnected to the same SSID within 15 s — `LOSS_GRACE_MS`; the window restarts after a resume, a reconnect inside it posts neither toast, so AP roaming and post-sleep reassociation are silent; any user Wi-Fi command cancels it).
- Renderer: Quick Menu process. One card at a time (info 4 s, warning/error 6 s), queue of 6, same id replaces in place. Live Notifications (any message carrying `progress=`, even -1) never time out (user request 2026-10-09): `Toasts.live` keeps the running ones (oldest first); a timed card shows over a running one for its usual time, then the oldest running one comes back; the completion (same id without `progress`) replaces it as a timed card. Sleep/power off drop timed cards but keep running ones (`Toasts::resume` shows them again); a completion or DISMISS received during the curtain or before a resume still ends a live one (`finish_hidden`).
- BACKGROUND TASK section (user request 2026-10-09): the QM's former unused CONTEXT block (`context-section-*`, row 29 = `TASK_ROW`, between the contextual sections and DISPLAY & AUDIO) shows the oldest running job whose Live Notification carries `cancel=1` (jobd sets it for running/queued jobs of a `CANCEL=1` type): title (+ ` · n%`) and Stop; second press (armed through `game-confirm-index`) runs `nuubos-jobctl cancel <n>` (id `job.<n>`), value "Stopping…" until its cancelled notification arrives. Storage jobs (nuubos-systemd) are not cancellable. Strings 808-810. The card has its own persistent layer surface (`Notifier`: second Slint window `NotificationWindow`, second `WaylandState` on its own event queue, 416x88 anchored top-right, card 14 px from top/right) that opening/closing the Quick Menu never touches; the open menu draws an identical copy at the same position so neither stacking order nor remapping flashes. Only the menu `WaylandState` publishes the mapped markers. Event → title/icon/severity mapping is `toast_view()` in `main.rs`. Hidden during the lifecycle curtain and cleared before Sleep; notifications received before a resume are dropped. Frames are produced only while `has_active_animations()` (marquee). Unmapping a layer surface (null-buffer commit) must go through `WaylandState::commit_unmap()`: wlroots resets the surface and forgets configures already sent, so acking one during the following roundtrip is a fatal "wrong configure serial" that kills the whole QM connection (seen 2026-10-05 as a frozen QM/Home after a volume OSD over a notification).
- Test on target: `nuubos-notifyctl post <id> <event> key=value …`, `nuubos-notifyctl watch`.
- Headless: `tools/ui-shot/run.sh` renders `notif_*` scenes.
