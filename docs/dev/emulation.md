# Emulation (RetroArch hybrid) and game UX

## Frozen direction (§18)
Hybrid model: RetroArch/libretro is the only backend (standalone emulators out of scope, EPIC-014 removed 2026-10-07). nuubOS exposes common recurring actions through native controller-first UI/Product APIs; `RetroArch Advanced` opens RetroArch's native menu for power users. Never reimplement the RetroArch configuration UI nor duplicate it in Settings → Gaming.
- §18.1 With a game running, the GAME section is at the TOP of the Quick Menu, before system controls.
- §18.2 Hotkeys/chords at least for Save State, Load State, change Save Slot, Fast Forward; `M` is the modifier layer while `M` alone opens the Quick Menu. Hotkeys go through the SAME Emulation Service/Product API as menu actions (no second direct RetroArch-control path in the input layer); a global OSD/notification confirms.

## RetroArch backend (§37.13, EPIC-013/019)
- Packages: `package/libretro/` — `retroarch` 1.22.2 (Wayland + EGL/GLES3 on Panfrost, udev joypads, ALSA + PipeWire, stdin commands; no X11/SDL/Vulkan/FFmpeg/KMS/slang), `retroarch-assets` (Ozone subset), `libretro-core-info`, 15 cores (matrix, licences and the non-commercial decision in `package/libretro/README.md`). `BR2_PACKAGE_NUUBOS_EMULATION` selects them all. Core build quirks live in `libretro.mk` (GCC 15 flags), `libretro-mgba` (CMake), `libretro-picodrive` (`-U_LARGEFILE64_SOURCE`). RetroArch patches: `0001` stdin `SAVE_STATE_SLOT n` / `SET_PAUSED 0|1` / `LOAD_STATE_SLOT n` with `OK|FAILED` newline-terminated replies (hotkey commands are edge-triggered bits that collapse within one frame and report nothing); `0002` Wayland EGL config for GLES2 contexts in a GLES3-only build (without it RetroArch segfaults at start).
- Service `nuubos-emud` (package `nuubos-emulation`, `S49nuubos-emud`, socket `/run/nuubos/emud.sock`, log `/run/nuubos/emud.log`, RetroArch stderr in `/run/nuubos/retroarch.log`, CLI `nuubos-emuctl status|watch|launch ID|pause|resume|save|load|slot N|+1|-1|reset|fast-forward|advanced|quit|pre-power ACTION`). Protocol like libraryd: `STATUS`/`SUBSCRIBE` snapshot (`state=idle|running|exiting`, `game=`, `system=`, `core=`, `paused=`, `slot=`, `fast_forward=`, `state_busy=`, `end=1`); `LAUNCH\t<game>` replies `OK` or `ERR busy|no-user|game|unavailable|no-core|library|storage|spawn`. One session at a time; idle = poll without timeout (timers only while a save/quit is pending); child exit via SIGCHLD self-pipe.
- Launch: libraryd `RESOLVE` → `cores.conf` (`/usr/share/nuubos/emulation/cores.conf`, `system|core,...`: first bundled core in `/usr/lib/libretro`, else first downloaded one in `/userdata/retroarch/cores`) → per-user dirs → `retroarch --config <user cfg> --appendconfig /run/nuubos/emulation/session.cfg -L core content` with stdin/stdout pipes, `setsid`, env `XDG_RUNTIME_DIR=/run/nuubos/wayland-runtime`, `HOME=<ra dir>`, `XDG_CONFIG_HOME=<user>/appdata`. libraryd `SESSION_BEGIN/END` around the process (Last/Time Played).
- Configuration layers: per-user `/userdata/users/<id>/appdata/retroarch/retroarch.cfg` seeded once from `/usr/share/nuubos/emulation/retroarch.cfg` (H700 defaults: vsync, no threaded video, pixel perfect presentation (below), ALSA 64 ms, SRAM flush 10 s, no rewind/run-ahead, analog→D-pad, Ozone, Reboot/Shut Down hidden, aarch64 buildbot core URL), `retroarch-core-options.cfg` seeded from the core option defaults (global core options), user edits in RetroArch Advanced kept (`config_save_on_exit`). The session config (written every launch) enforces paths, drivers, ports, stdin commands (UDP network commands never), `quit_on_close_content`, OK = RetroPad A, language from the user's nuubOS language. Saves `/userdata/users/<id>/saves/<system>`, states `.../states/<system>` (`<rom name>.state[N]`, automatic slot `.state.auto`), screenshots `.../screenshots`, BIOS `/userdata/bios` (shared), cache `/userdata/cache/retroarch`.
- Controllers: games only see `nuubOS Gamepad` uinput devices from nuubos-inputd (one per player, product id = player, vendor 0, `/devices/virtual/input`; RetroArch reserves port N for `0000:000N`; autoconfig `/usr/share/retroarch/autoconfig/udev/nuubOS Gamepad.cfg`: SOUTH..THUMBR = buttons 0..11, D-pad hat 0, axes X/Y/RX/RY 0..3). controllersd pushes the resolved table on every device/user/mapping/deadzone/assignment change (`PADMAP BEGIN`, `PADMAP <id> player=N left_deadzone= right_deadzone= <control>=<source>...`, `PADMAP END`). emud sends `GAMEPADS ON` and keeps that connection: gamepads go off when it closes. While on, inputd grabs every controller; game controls go to the player's game gamepad (nothing while the Quick Menu is open, everything released when it opens), no nuubUI navigation leaks to Home. udev rule `71-nuubos-game-gamepads.rules` clears `ID_INPUT_JOYSTICK` (and sets `LIBINPUT_IGNORE_DEVICE`) on physical controllers so RetroArch/SDL never take them as extra players.
- Hotkeys (CLAUDE §18.2, user request 2026-10-08): in a game the Quick Menu button (Hotkey) is a modifier; alone it opens the Quick Menu on release. Defaults H+R1 save state, H+L1 load state, H+Up/Down slot +/-, H+North fast-forward, H+Start quit (auto-saves), H+L2 screenshot; remappable per user in Settings → Gaming → Game Hotkeys (page 55, dropdown of the 16 logical controls). emud owns them (`hotkey_<action>` in the user's emulation settings) and sends `HOTKEYS <action>=<control> ...` to inputd after `GAMEPADS ON` (and on every change/reconnect); inputd falls back to its defaults otherwise. Chords also work for controls bound to an axis (hat D-pad, analog triggers: same 50/30 % thresholds, edge-detected while the modifier is held). inputd writes `HOTKEY <action>` on emud's gamepads connection; emud runs the same code as the Quick Menu commands.
- User emulation settings (Settings → Gaming, user request 2026-10-08): emud `SETTINGS` / `SET <key> <value>`, stored in `/userdata/users/<id>/appdata/nuubos-emulation/settings.conf`: `boot_screens` (0; rewrites the boot keys of the user's core options at launch: `pcsx_rearmed_show_bios_bootlogo`, `mgba_skip_bios`, `gambatte_gb_bootloader`, `genesis_plus_gx_bios`, `melonds_boot_directly`), `slots` (10, 1-99), `slot_rotation` (1), `bezels` (0), `crt` (0), `overlay` (0), `overlay_items` (`fps,cpu,ram,temp,battery,clock`; also `gpu`, `power`; `ram` = systemd PERF `mem.used_mib`, battery shown as `BAT n%`), `hotkey_*`. Hotkeys and overlay apply live to a running game of that user, the rest at the next launch. Gaming page rows: RetroAchievements, Console Boot Screens, Save State Slots, Rotate Save Slots, Game Hotkeys, Performance Overlay (page 56), Bezels, CRT Effect, then LIBRARY from `gaming-split`.
- Save states (EPIC-019, user request 2026-10-08): RetroArch writes `.state.auto` whenever the game closes (`savestate_auto_save` in the session config). `LAUNCH <game> [resume|new|slot:N]`: resume (default, Home short press, Details Play) starts from the most recent state (auto or numbered, by mtime: auto → `savestate_auto_load`, slot → `--entryslot N`), new from the beginning, `slot:N` from that slot (`-1` = auto). Rotation: a save goes to the selected slot if empty, else to the next one (wrapping to 0); the saved slot becomes the selected one (Load State loads the latest save). At launch the selected slot is the start slot or the most recent numbered one. `STATES [game]` lists `slots=N` + `state=<slot>\t<mtime>\t<HH:MM>`. Home: holding Confirm 600 ms on a game card opens Start Game (page 57 in the Details shell: Continue, every state with its time, Start from the Beginning); Home now gets `menu_confirm released` from inputd and launches on release.
- Quick Menu over a game: GAME section first (Resume, Save State, Load State, State Slot (a dropdown only, user request 2026-10-08: confirm opens every slot with its save time or Empty, left/right do nothing), Restart Game, RetroArch Advanced, Screenshot, Performance Overlay (row 28, switch = the user's `overlay` setting via emud `SET`, applied live), Quit Game; Load/Restart/Quit need a second press); QM dropdowns open above their row when the screen ends first; opening pauses (`PAUSE`), every close resumes (`RESUME`) except Quit and RetroArch Advanced. Switch User is hidden over a game. The power key opens the Power OSD (quick-menu-notify.md) over the game, which waits paused underneath.
- Sleep with a game running (fixed 2026-10-08): `panfrost_device_suspend` returned -EBUSY whenever a job was still on the GPU at freeze time (a game always has one), aborting s2idle ("PM: Some devices failed to suspend"); Home alone never hit it because it is idle. Kernel patch `0029-drm-panfrost-wait-for-jobs-before-system-suspend.patch` waits up to 1 s for the queued jobs (user space is already frozen). Hardware-confirmed: N64 running, s2idle entered, auto state written, wake by a key.
- Outcomes are notifications (`game.state.saved|loaded|empty|failed`, `game.slot`, `game.fastforward`, `game.failed reason=start|crash`); state saves are confirmed only when the file is closed (inotify `IN_CLOSE_WRITE`/`IN_MOVED_TO` on the state dir, 10 s timeout).
- Lifecycle: `/usr/lib/nuubos/lifecycle-hooks/pre-power.d/50-emulation` → `nuubos-emuctl pre-power <action>`: saves the automatic state slot before Sleep/Restart/Power Off and, for Restart/Power Off, quits RetroArch (SRAM written) before replying (quit timeout 10 s, then SIGTERM, then SIGKILL of the process group). The CLI gives up after 25 s.
- Home: `library.rs` `launch_game` / `start_game_listener` (`GAME_RUNNING`); `on_game_session` stops Home Music while a game runs and restarts it after. Home keeps its inputd UI capture: inputd routing ignores it while gamepads are on.

## Presentation, CRT, bezels, overlay, performance (user request 2026-10-08)
- Pixel perfect (A/B): without a per-game aspect override every game uses square pixels (`aspect_ratio_index` 21), integer scale in RetroArch's smart mode (`video_scale_integer_scaling` 2) and `video_viewport_bias_y` 0 (top of the screen, margin left at the bottom). RetroArch patch `0003`: smart mode never falls back to non-integer scaling (stock: below 88 % screen use) and an overscaled picture crops its overscan evenly (the bias only places smaller pictures). Exception (user request 2026-10-08, PSP was "molto piccolo"): content that would stay at 1x with more than 12 % of the screen unused (PSP 480x272, NDS on 640x480) is scaled to fit with its aspect instead; anything reaching 2x (GBA, N64, SNES...) stays integer. The bezel shader applies the same rule (fits inside the frame: 44/22 px of 480p room). Per-game Aspect Ratio still offers As the game/4:3/16:9/Full Screen. emud writes all presentation keys at every launch (remembered and restored like the other session keys) and passes `--set-shader <preset>` (empty = no shader, also disables RetroArch's automatic presets).
- CRT Effect (L): `shaders/crt.glsl` (nuubOS, MIT): horizontal melt between neighbours + brightness-dependent beam per source line, centred half an output row up so 2x gives beam/gap rows; no scanlines below 2x vertical scale; two fetches. Applies only to `crt` systems of `display.conf` (`crt|lcd|monitor`, missing = monitor) and only without a per-game filter; session preset `/run/nuubos/emulation/session.glslp`.
- Bezels (I): `shaders/bezel.glsl` (nuubOS, procedural, MIT; no artwork so no licensing and every resolution/geometry works): RetroArch viewport = whole screen (aspect 24, no integer), the shader places the picture itself (largest integer scale, centred, top) and draws a matte background tinted with the system colour (`systems.conf` field 6), a rounded frame (TV style, or handheld body for `lcd` systems) and a thin accent line; parameters `BEZEL_R/G/B`, `BEZEL_STYLE`, `CRT` (same CRT look) in the session preset. Not applied with a per-game aspect override.
- Performance overlay (G): RetroArch patch `0003` adds stdin `GET_FPS` (frames presented since the previous call). While a game of a user with `overlay=1` runs and is not paused, emud asks it once a second (timer only then) and publishes `fps=` with `overlay=`/`overlay_items=` in its snapshot; the Quick Menu builds the line from the snapshot plus nuubos-systemd `PERF` (`cpu.load_pct` since the previous call, `cpu.freq_khz`, `gpu.freq_hz`, temps, `battery.percent` shown as `BAT n%`, `battery.power_mw` = voltage x current, `mem.used_mib` for `ram`) and its clock, and sends it to emud `OVERLAY_TEXT\t<line>` only when it changes ("" hides it: Quick Menu open, paused, lifecycle curtain); emud forwards `OSD_TEXT <line>` on RetroArch's stdin. RetroArch patch `0004` draws it INTO the game frame through the statistics path (top left, ~15 px per 480 lines, white with a dark shadow, OSD font = Cantarell Bold: emud writes `video_font_enable/path/size` as remembered session keys; RetroArch notifications use widgets, not this font). Since 2026-10-08 (user request) there is no overlay layer surface any more: a layer over the game made labwc composite every frame and cost ~10 % on GPU-bound games (Majora's Mask PAL 50 -> 45 fps); in-frame it costs nothing measurable and the game stays on direct scan-out (one DRM plane). Gotcha fixed in `0004`: GLideN64's threaded renderer leaves pixel-unpack state bound and the font atlas upload then crashed Mesa in `dri_flush` at the next swap (RetroArch exit 11 ~16 s after launch); gl2 saves/resets/restores `GL_PIXEL_UNPACK_BUFFER` + unpack row length/skips/alignment around the statistics text. QM GAME row 28 toggles the user's `overlay` live (emud `SET`).
- Measured 2026-10-08 (RG40XX-V, Majora's Mask): RetroArch is scanned out directly (XR24 linear buffer imported by labwc: "allocated by labwc" in the DRM state is the import, not composition). With upstream GLideN64 options the main thread used ~53 % and the GPU sat at 600 MHz; `nuubos-mediad` burnt a whole core since boot (its `deadline_ms` started at 0: poll timeout 0, fixed) and `ksmbd.mountd` restarted its worker every second (Kerberos built in through libkrb5 without a keytab → abort; fixed by `patches/packages/ksmbd-tools/0001`). N64 defaults now: `ThreadedRenderer`, no color/depth copy to RDRAM, no HybridFilter, texture cache limit 1500; PSP: native resolution, skip GPU readbacks, lazy texture caching, low spline quality, lower resolution for effects (Safe). New core option defaults reach existing users only for keys they do not have yet (merge rule above). The user's N64 crash after 20-30 s did not reproduce (Majora's Mask, ~10 min with the old options and again with the new ones); if it returns, use the core dump procedure above.
- Audit 2026-10-08 (RG40XX-V, user request "limare ancora"): the Majora's Mask test ROM is PAL (header region `P`): 50 fps is full speed, NOT a slowdown (check the region before reading N64 fps). GET_FPS counts video refresh calls; with the surface of the overlay hidden (`overlay=1`, `overlay_items=` empty: emud still polls, the QM maps nothing) it reads 50.0, with the overlay shown 45.0: the overlay forces labwc composition and costs ~10 % speed on a GPU-bound game (GPU pinned at 600 MHz) and doubles labwc CPU (PSP homebrew: 5.9 → 12.6 %). No effect measured from: CRT shader, GLideN64 HybridFilter/texture cache 1500/FB emulation/LOD emulation, CPU `performance` governor (CPU at most ~80 % of 400 %), schedutil `rate_limit_us` 10 ms instead of 976 µs (450 → 93 freq changes/s, sugov 3 → 1.3 %, but fps dipped: kept). Not changed: GPU OPPs 432–600 MHz @ 940 mV (qualified, platform.md), DRAM 1344 MHz. Done since: overlay drawn inside RetroArch's frame (above).
- PSP audit 2026-10-08 (God of War: Chains of Olympus, EU ISO, in-game fight): ~9-10 presented fps with the GPU fragment engine only 44 % busy (panfrost `profiling`=1 + `drm-engine-*` in fdinfo; set it back to 0) and the GL thread (`Main`) ~30 % in `dma_fence_default_wait`. Root causes found with core dumps taken while that thread waited (`ioctl DRM_IOCTL_PANFROST_WAIT_BO`): (1) `GLQueueRunner::PerformCopy` -> `glCopyImageSubData`, a CPU copy in Panfrost (`util_resource_copy_region` maps both textures and waits); (2) `OpenGLContext::UpdateBuffer(UPDATE_DISCARD)` doing a partial `glBufferSubData` into the presentation vertex buffer the previous frame still reads (a full CPU/GPU serialization every frame); (3) push buffers via `glBufferSubData`. `package/libretro/libretro-ppsspp/0001-gl-avoid-gpu-waits-on-mesa-panfrost.patch` (Mesa + "Mali" renderer only for 1 and 3): blits instead of image copies, whole-buffer upload on discard (Panfrost then allocates a fresh BO), push buffers mapped with `GL_MAP_INVALIDATE_BUFFER_BIT`. Measured in the same fight: ~9-10 -> ~12 (blits) -> ~16 (discard) -> ~17.8 (invalidate, A/B twice): about 2x; the GL thread no longer waits, it is now CPU-bound. A Mesa patch shadowing busy textures on partial writes was tried and measured with no gain: dropped. Anisotropic 16x -> disabled: ~+10 % (shipped default). `ppsspp_skip_buffer_effects` gives 60 fps but a BLACK screen in God of War: never default it. Core dumps on target: `/tmp` is a 491 MB tmpfs (cores get truncated) and exFAT `/userdata` writes empty cores: use `core_pattern` = `|/tmp/coregz.sh` (`exec gzip -1 > /userdata/...`), put `core` back afterwards; kill with SIGABRT (no auto-save). gdb: `set sysroot output/h700/target` + `solib-search-path` target/usr/lib/libretro:target/usr/lib:target/lib (target libs keep `.symtab`). Never quit a test game started with `launch ... new` or killed mid-test without backing up `<game>.state.auto`: RetroArch writes it on every quit (Majora's auto state was lost that way on 2026-10-08; numbered slots were intact).

- Mesa 25.0.6 panfrost heap overflow (found 2026-10-08, HDMI): `pan_cast_and_pack(dst, ...)` casts `dst` without parentheses, so `pan_fb_preload.c` packed the Bifrost padding ATTRIBUTE_BUFFER at `cpu + 16 * 16` (+256) instead of +16: every framebuffer preload wrote 16 bytes past a 32-byte pool allocation (silent descriptor corruption; SIGSEGV in `pan_preload_emit_pre_frame_dcd` under `eglSwapBuffers` when the allocation ended a 64 KB slab, typically after a window resize: RetroArch status 11 a few seconds after launch or on an HDMI mode change, with or without GLideN64's threaded renderer). Fix: `patches/packages/mesa3d/25.0.6/0002-panfrost-parenthesize-pan_cast_and_pack-dst.patch`. The RetroArch `0004` "font atlas crashed Mesa in dri_flush" gotcha may have been this same bug.
- N64 speed vs HDMI output size (Majora's Mask PAL, bezels+CRT on, same save slot, 2026-10-08): 640x480 50 fps (full), 1024x768 34, 1280x720 27, 1920x1080 16: with bezels/CRT the frontend's per-output-pixel cost dominates (GLideN64 itself renders at 320x240). Measure from a fixed numbered slot (`nuubos-emuctl launch GAME slot:N`): the automatic state is rewritten on every quit, so successive launches load different scenes (36 vs 51 fps at the same mode). Before kernel `0031` a smaller wp_viewporter-scaled buffer only reached 38 fps at 480 lines (labwc composited it on the GPU).
- Game render height on HDMI (user request 2026-10-08: TV stays at 1080p, the game is rendered small and stretched): emud reads `/sys/class/drm/card0-HDMI-A-1/enabled` at launch and, when HDMI is the active output, passes `NUUBOS_RA_RENDER_HEIGHT=<lines>` to RetroArch; RetroArch patch `0005` sizes its window buffer at that many lines (width from the output aspect: 640x360 on 16:9) and sets the wp_viewporter destination to the full surface; wlroots scans the buffer out on the HDMI primary plane (DE33 VI channel 2) scaled by the display engine (kernel `0031`), no GPU composition. Lines = `display.conf` field 3 (`system|screen|lines`, 0 = native), default 360 (`GAME_HDMI_LINES`): Majora's Mask PAL 49-51 fps (854x480: 45-46, 1080p native: 16). Below 480 lines 240p content fits at 1.5x, so the CRT look draws no scanlines (needs 2x). The panel never gets the variable. emud logs `render=N` per launch. Users saw the scaled picture as slightly darker than the native one in an A/B (not explained: the shader applies no brightness at 1.43x, the scaler uses the stock Lanczos tables).
