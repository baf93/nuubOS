# Emulation (RetroArch hybrid) and game UX

## Frozen direction (§18)
Hybrid model: RetroArch/libretro is the only backend (standalone emulators out of scope, EPIC-014 removed 2026-10-07). nuubOS exposes common recurring actions through native controller-first UI/Product APIs; `RetroArch Advanced` opens RetroArch's native menu for power users. Never reimplement the RetroArch configuration UI nor duplicate it in Settings → Gaming.
- §18.1 With a game running, the GAME section is at the TOP of the Quick Menu, before system controls.
- §18.2 Hotkeys/chords at least for Save State, Load State, change Save Slot, Fast Forward; `M` is the modifier layer while `M` alone opens the Quick Menu. Hotkeys go through the SAME Emulation Service/Product API as menu actions (no second direct RetroArch-control path in the input layer); a global OSD/notification confirms.

## RetroArch backend (§37.13, EPIC-013/019)
- Packages: `package/libretro/` — `retroarch` 1.22.2 (Wayland + EGL/GLES3 on Panfrost, udev joypads, ALSA + PipeWire, stdin commands; no X11/SDL/Vulkan/FFmpeg/KMS/slang), `retroarch-assets` (Ozone subset), `libretro-core-info`, 15 cores (matrix, licences and the non-commercial decision in `package/libretro/README.md`). `BR2_PACKAGE_NUUBOS_EMULATION` selects them all. Core build quirks live in `libretro.mk` (GCC 15 flags), `libretro-mgba` (CMake), `libretro-picodrive` (`-U_LARGEFILE64_SOURCE`). RetroArch patches: `0001` stdin `SAVE_STATE_SLOT n` / `SET_PAUSED 0|1` / `LOAD_STATE_SLOT n` with `OK|FAILED` newline-terminated replies (hotkey commands are edge-triggered bits that collapse within one frame and report nothing); `0002` Wayland EGL config for GLES2 contexts in a GLES3-only build (without it RetroArch segfaults at start).
- Service `nuubos-emud` (package `nuubos-emulation`, `S49nuubos-emud`, socket `/run/nuubos/emud.sock`, log `/run/nuubos/emud.log`, RetroArch stderr in `/run/nuubos/retroarch.log`, CLI `nuubos-emuctl status|watch|launch ID|pause|resume|save|load|slot N|+1|-1|reset|fast-forward|advanced|quit|pre-power ACTION|storage-lost MOUNT`). `STORAGE_LOST\t<mount>` (nuubos-storagectl, games card pulled out): a session whose ROM is under it takes the automatic state (not in hardcore), quits like before a power off and posts `game.storage_lost`. Every session end that is not a power action runs `nuubos-sd2-backup trigger session-end`. Protocol like libraryd: `STATUS`/`SUBSCRIBE` snapshot (`state=idle|running|exiting`, `game=`, `system=`, `core=`, `paused=`, `slot=`, `fast_forward=`, `state_busy=`, `end=1`); `LAUNCH\t<game>` replies `OK` or `ERR busy|no-user|game|unavailable|no-core|library|storage|spawn`. One session at a time; idle = poll without timeout (timers only while a save/quit is pending); child exit via SIGCHLD self-pipe.
- Launch: libraryd `RESOLVE` → `cores.conf` (`/usr/share/nuubos/emulation/cores.conf`, `system|core,...`: first bundled core in `/usr/lib/libretro`, else first downloaded one in `/userdata/retroarch/cores`) → per-user dirs → `retroarch --config <user cfg> --appendconfig /run/nuubos/emulation/session.cfg -L core content` with stdin/stdout pipes, `setsid`, env `XDG_RUNTIME_DIR=/run/nuubos/wayland-runtime`, `HOME=<ra dir>`, `XDG_CONFIG_HOME=<user>/appdata`. libraryd `SESSION_BEGIN/END` around the process (Last/Time Played).
- Configuration layers: per-user `/userdata/users/<id>/appdata/retroarch/retroarch.cfg` seeded once from `/usr/share/nuubos/emulation/retroarch.cfg` (H700 defaults: vsync, no threaded video, pixel perfect presentation (below), ALSA 64 ms, SRAM flush 10 s, no rewind/run-ahead, analog→D-pad, Ozone, Reboot/Shut Down hidden, aarch64 buildbot core URL), `retroarch-core-options.cfg` seeded from the core option defaults (global core options), user edits in RetroArch Advanced kept (`config_save_on_exit`). The session config (written every launch) enforces paths, drivers, ports, stdin commands (UDP network commands never), `quit_on_close_content`, OK = RetroPad A, language from the user's nuubOS language. Saves `/userdata/users/<id>/saves/<system>`, states `.../states/<system>` (`<rom name>.state[N]`, automatic slot `.state.auto`), screenshots `.../screenshots`, BIOS `/userdata/bios` (shared), cache `/userdata/cache/retroarch`.
- Controllers: games only see `nuubOS Gamepad` uinput devices from nuubos-inputd (one per player, product id = player, vendor 0, `/devices/virtual/input`; RetroArch reserves port N for `0000:000N`; autoconfig `/usr/share/retroarch/autoconfig/udev/nuubOS Gamepad.cfg`: SOUTH..THUMBR = buttons 0..11, D-pad hat 0, axes X/Y/RX/RY 0..3). controllersd pushes the resolved table on every device/user/mapping/deadzone/assignment change (`PADMAP BEGIN`, `PADMAP <id> player=N left_deadzone= right_deadzone= <control>=<source>...`, `PADMAP END`). emud sends `GAMEPADS ON` and keeps that connection: gamepads go off when it closes. While on, inputd grabs every controller; game controls go to the player's game gamepad (nothing while the Quick Menu is open, everything released when it opens), no nuubUI navigation leaks to Home. udev rule `71-nuubos-game-gamepads.rules` clears `ID_INPUT_JOYSTICK` (and sets `LIBINPUT_IGNORE_DEVICE`) on physical controllers so RetroArch/SDL never take them as extra players.
- Hotkeys (CLAUDE §18.2, user request 2026-10-08): in a game the Quick Menu button (Hotkey) is a modifier; alone it opens the Quick Menu on release. Defaults H+R1 save state, H+L1 load state, H+Up/Down slot +/-, H+North fast-forward, H+Start quit (auto-saves), H+L2 screenshot; remappable per user in Settings → Gaming → Game Hotkeys (page 55, dropdown of the 16 logical controls). emud owns them (`hotkey_<action>` in the user's emulation settings) and sends `HOTKEYS <action>=<control> ...` to inputd after `GAMEPADS ON` (and on every change/reconnect); inputd falls back to its defaults otherwise. Chords also work for controls bound to an axis (hat D-pad, analog triggers: same 50/30 % thresholds, edge-detected while the modifier is held). inputd writes `HOTKEY <action>` on emud's gamepads connection; emud runs the same code as the Quick Menu commands. Quit everywhere (user bug 2026-10-29: H + Start did nothing in the terminal and PortMaster): the Quit chord also ends ports/PortMaster (portsd `request_quit`), PC streams (streamd `request_stream_quit(false)`: the host app follows the user's quit-app setting), the terminal and the browser (termd/webd `quit_session`); in WEB/TERMINAL mode inputd lets only the Quit chord through (the other chords stay swallowed). Verified on the CubeXX 2026-10-29 for the terminal and PortMaster; streaming not tried (no host), the browser is not in the image.

- Save states (EPIC-019, user request 2026-10-08): without slot rotation RetroArch writes `.state.auto` whenever the game closes (`savestate_auto_save` in the session config). With slot rotation (user request 2026-10-11, the default) the automatic save follows the rotation: `savestate_auto_save` is off and emud saves quietly into `save_target()` before asking RetroArch to quit (`request_quit`: `quit_requested`/`quit_saved`, once; a failed or timed-out save still quits) and on `PRE_POWER` (sleep: the game keeps running with that slot selected; restart/poweroff: the quit does not save again). Gap: Close Content from RetroArch Advanced's own menu bypasses emud, so with rotation nothing is saved then. `LAUNCH <game> [resume|new|slot:N]`: resume (default, Home short press, Details Play) starts from the most recent state (auto or numbered, by mtime: auto → `savestate_auto_load`, slot → `--entryslot N`), new from the beginning, `slot:N` from that slot (`-1` = auto). Rotation: a save goes to the selected slot if empty, else to the next one (wrapping to 0); the saved slot becomes the selected one (Load State loads the latest save). At launch the selected slot is the start slot or the most recent numbered one. `STATES [game]` lists `slots=N` + `state=<slot>\t<mtime>\t<HH:MM>`. ## Game UX: Details, per-game settings, screenshots, BIOS, metadata, achievements (§37.18)
- libraryd: `DETAILS\t<game>` (game line + `system_name= sessions= path= size= added=`, `member=<cid>\t<name>\t0|1` per collection, `meta_<key>=` from `/userdata/library/metadata/<system>/<rom stem>.txt`), `STATS_RESET\t<game>|all`, `DELETE\t<game>\tCONFIRM` (ROM + files its .m3u/.cue own, two levels, not ones another available game references; cover in the covers store and metadata removed; saves/history kept; `ERR busy` for the game in session; main file last; an unavailable game (user request 2026-10-20: it had no Delete and kept its metadata) loses only its catalog entry, store cover, metadata and `.tried` mark, no file touched — also when it sits on an SD2 that is not inserted; Game Details shows Delete Game for it too with caption 1318, the web page the same). CLI: `nuubos-libraryctl details|hide|stats-reset|delete GAME confirm`. Host test `python3 package/nuubos/nuubos-library/tests/details-delete.py`.
- emud per-game overrides: `GAME_SETTINGS\t<game>\t<system>` → `core= core_default= core_override= cores=a,b aspect= filter= filter_default=crt|sharp end=1` (filter_default = what an empty filter gives: `crt` for a `crt` system with the user's CRT Effect on; the Video Filter row shows "Default (CRT Effect)"); `GAME_SET\t<game>\t<system>\t core|aspect|filter\t<value or empty>` (aspect core|4:3|16:9|full|integer, filter sharp|smooth|pixel, core must be an available core of the system); also `accuracy`, `pak` and `resolution` (below); `GAME_RESET\t<game>`. Stored only as overrides in `/userdata/users/<id>/appdata/nuubos-emulation/games/<game>.conf` (so Reset User Profile clears them). Applied at launch in the session config; keys a session overrides (aspect/scale/shader/smooth/cheevos_*) are snapshotted from the user's retroarch.cfg and restored when RetroArch exits (RetroArch saves its config on exit). Emud roots are `#ifndef` overridable; host test `python3 package/nuubos/nuubos-emulation/tests/game-settings.py` (real libraryd + emud + fake RetroArch).
- Screenshots: emud `SCREENSHOT` (RetroArch stdin `SCREENSHOT`, RetroArch's own rendering) confirmed by inotify on the user's screenshot dir (new `.png` closed within 5 s) → `game.screenshot.saved|failed`. Hotkey M+L2 (inputd `screenshot`), QM GAME row 18 (between RetroArch Advanced and Quit Game; geometry 6 steps, Quit moved to 7).
- RetroAchievements: `nuubos-achievementsctl status|login USER NAME (password stdin)|logout|set USER enabled|hardcore 0|1` (libcurl, rcheevos `login2` endpoint; only the token is stored, `/state/users/<id>/secrets/retroachievements.conf` 0600). ## Square screens, bezel cost, overscan (2026-10-11, RG CubeXX 720x720)
- Measured on the CubeXX (bezels + CRT on, the user's settings): SNES 48 fps, GB 56, PS1 42, N64 Doom 64 27; with bezels off all 60 (N64 37-44). - Fix: two-pass preset (emud `write_session_shader(..., cached)`): pass 0 `bezel.glsl` draws only the bezel into an FBO (`scale_type0 viewport`, `feedback_pass 0`) and reads it back from the previous frame (`FeedbackTexture`) when its alpha holds the same key of the picture rectangle; one row in 16 is redrawn per frame (heals key collisions); placement is computed per vertex. Pass 1 `bezel-picture.glsl` draws the picture from `OrigTexture` and the bezel from the FBO. After: SNES/GB 60.0, PS1 PAL 50 (full), N64 Mario 64/Mario Kart PAL 50 (full), Doom 64 33-36 (37-44 without bezels: the game itself).
- Multi-pass gotchas (GLSL legacy, gl2): (1) give the LAST pass no `scale_type`: with one RetroArch adds its own stock pass after it, the pass becomes an FBO pass and clip-space Y is flipped for software cores only (bottom-left-origin hw cores not); (2) FBO passes run in the core frame's orientation, so pass 0 addresses rows by `gl_FragCoord` (row 0 = top by convention) and pass 1 reads them back by screen position; (3) a `#pragma parameter` declared in two passes becomes two entries: the preset sets only the first and the second (default) overwrites the uniform: declare each parameter in one pass only; (4) RetroArch compiles these as GLSL ES 1.00 (`varying`/`gl_FragColor` path, no `dFdy` without the extension).
- 4:3 TV systems on square screens (user decisions 2026-10-11): emud sets `NUUBOS_RA_OVERSCAN_X=1` / bezel `OVERSCAN_X` only for `crt` systems with the default presentation on an enabled square built-in panel (`square_panel()`: never HDMI, 4:3 or 3:2). ## PortMaster (EPIC-058, RC3 plan item 1): analysis 2026-10-24
