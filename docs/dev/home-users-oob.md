# General/Users, OOB, Home and Game Library

## General / users (§14)
Settings → General has User and Device areas; no space wasted on a generic category description. User: username/profile info, profile picture (default licensed avatar collection + user pictures from a per-user location), manage other users, create, delete with confirmation, startup user-selection behavior, default boot user. Device: date/time, timezone, automatic time sync, keyboard layout, startup behavior, Manage Users. Switch User performs a REAL user/session switch. The User Picker follows nuubOS grammar (top bar + bottom hint bar). With ≥2 users, product settings choose between the picker at boot and a configured default user.
- Built-in avatars (gaming style, 2026-10-07 user request): 20 DiceBear 10.x PNGs 256 px on retro-palette square backgrounds (01-10 Voxel Art, 11-20 Voxel Bot, all CC0 1.0; code MIT; Pixel Art dropped 2026-10-10 on user request, set renumbered: a stored `builtin:NN` outside 01-20 is reset to 01 by usersd at start) regenerated by `tools/avatars/generate.sh`; attribution in `nuubos-users/src/avatars/README.txt` + `LICENSE-DiceBear.txt`. The UI shows every avatar as a rounded square.

## OOB / first boot (§15, EPIC-002)
Flow confirmed 2026-10-05, changed 2026-10-07 on explicit user request (Language step replaces Welcome): Language → Date & Time (timezone, automatic time, manual date/time) → Wi-Fi (skippable) → Users (≥1 user: name + avatar; Startup/Boot User when >1) → Ready → Home (or the user picker when the login mode requires it). Minimal, controller-first, nuubOS grammar. Same Product Services/contracts as Settings (no OOB-only logic/config stack); Date & Time reuses General timezone/automatic-time. Shown only while setup is incomplete; completion persists setup-complete. Implemented 2026-10-05.

- State owner: `nuubos-usersd`. `SETUP_COMPLETE=0|1` in `/state/config/nuubos.conf`; STATUS/SUBSCRIBE snapshots carry `setup_complete=`; `selection_required` is 0 while setup is pending. `COMPLETE_SETUP` (≥1 user, else `ERR no users`) fixes DEFAULT_USER if invalid, activates the default user when there is one user or login mode DEFAULT (before committing the flag, so a failed activation stays resumable), then writes the flag. `nuubos-usersctl complete-setup` does the same.
- S03: config v6. New configs get `SETUP_COMPLETE=0`; v1–v5 migrate to v6 with `SETUP_COMPLETE=1` only if a user profile exists (dev cards provisioned by `scripts/provision-state.sh` without users still get the OOB). While pending, S03 creates no "Player 1" and publishes no active user. A missing key in usersd counts as complete.
- UI (nuubui-home): `apply_users()` enters/leaves the OOB from the usersd snapshot (`enter_oob`/`leave_oob`, static `OOB_ACTIVE` routes input to `handle_oob_action`, Start is ignored, ui-context `oob` hides QM Switch User, inputd settings capture on). Entering step 1 offers, once per session, a restore of the whole console from any visible backup (SD2, USB drive; `storageui::offer_restore`, title 1023: this console's backup first, "Start from Scratch"); a restore ends in a restart. Steps: 0 Language and 4 Ready full-screen (`oob-hero`); 1 Date & Time = settings-view 30, 2 Wi-Fi = 31 (+ reused 2/4/6), 3 Users = 32 (+ reused 26 user detail, keyboard purpose 9). The Settings rail shows the steps. Wi-Fi step: when a connection is established while on the reused list (2) or network page (4), `apply_wifi_product_state` returns to step 31 with Continue focused (2026-10-07, user request: no detour through the network page after connecting); a failure keeps the user on the page with the error. Date & Time rows share `date_time_row_action()` with General rows 6–9. Every step commits immediately through the owning service, so an interrupted OOB restarts at Welcome with committed values kept.
- Preferences set before any profile exists (OOB, user picker) live under the pseudo-user `/state/users/default` (controllersd `controllers/` + `controllers.conf`, rumbled `input-feedback.conf`, lightingd `lighting.conf`, `localization.conf`). Since 2026-10-22 usersd copies those the profile lacks into the FIRST profile it creates (`adopt_default_prefs`; host-tested with a relocated usersd: first profile gets them, a second one starts clean, dot-files skipped); later profiles keep the defaults.
- Language step (step 0, full-screen `oob-hero`): "Welcome" endonyms (not translated, order = `UI_LANGUAGES` in main.rs) roll on a drum (Slint `Timer` 2.6 s, running only on step 0; `greet-tick` animated 700 ms, scale-y fakes the rotation) above a `‹ Language ›` selector: left/right (or up/down) → `SET LANGUAGE` to localizationd, A → Date & Time. Language stays a per-user preference: with no active user localizationd writes `/state/users/default/localization.conf` (= device language), and a user without an own `localization.conf` gets the device language (else en), so the first user inherits the OOB choice.
- User picker (2026-10-11): cards sized from the free height between the bars (78 %, 194-440 px, width ≤ 50 % of the screen on square panels), avatar = card width - 36 px (80 % when not focused). Closing the picker keeps the Home-wide inputd navigation capture (`sync_picker_capture` always sends `SETTINGS OPEN`): it used to send `SETTINGS CLOSE`, and after a boot through the picker inputd stopped routing the sticks (stick navigation only works under capture; buttons were unaffected).
- Creating a user (OOB or Settings → Manage Users) opens the avatar picker on the new user. The name keyboard (purposes 8/9, empty field) starts with Shift on (one-shot) so names begin capitalized.
- Test on target without reflashing: `sed -i 's/^SETUP_COMPLETE=.*/SETUP_COMPLETE=0/' /state/config/nuubos.conf` then `reboot` (existing users stay and are listed in the Users step). Headless: `tools/ui-shot/run.sh` renders `oob_*` scenes.

## Home (§16)
Close to the visual reference with native adaptive layouts: top status bar, hero, Recently Played, game metadata, Systems & Collections, Applications, controller hint bar. Home Music: MP3s from the active user's `music` dir, shuffled, own persistent volume; Quick Menu shows Skip while it plays; no audio routing/mixing logic in Home (audio.md).

## Home and Game Library (§37.11, EPIC-001/011/012/020)
- Owner `nuubos-libraryd` (package `nuubos-library`, `S47nuubos-library`, socket `/run/nuubos/libraryd.sock`, log `/run/nuubos/libraryd.log`, CLI `nuubos-libraryctl`). Same text protocol as usersd: `STATUS`/`SUBSCRIBE` snapshot ending in `end=1` (`recent=`, `collection=`, `system=`, `app=` lines), `GAMES\t<scope>` (`system:<id>`, `favorites`, `collection:<id>`, `recent`), `SESSION_BEGIN/END\t<game>` (Last Played/Time Played, sessions capped at 12 h), `SESSION_RECORD\t<game>\t<s>`, `FAVORITE\t<game>\t0|1`, `COLLECTION_CREATE/RENAME/DELETE/ADD/REMOVE`, `SCAN` (a request during a scan queues one more; snapshot `scanning=`, `games=` available, `scan_new=` games added or available again since the last `SCAN` received while idle, accumulated over a queued rescan; `games_root=` where new games go (the games card's ROM folder while SD2 is `ready`, else `/userdata/roms`; refreshed at every scan, as the SD2 folder); Settings → Gaming → Scan for New Games). Idle = 0 wakeups (poll without timeout, scan on a thread, active user via inotify on `/run/nuubos/user`).
- System registry (single source): `/usr/share/nuubos/systems.conf` (`id|name|folder|exts|cover aspect x1000|colour|folder aliases`), icons `/usr/share/nuubos/systems/<id>.png` (libretro retroarch-assets XMB Monochrome, CC BY 4.0, attribution in `nuubos-library/src/systems/ATTRIBUTION.txt`; naomi and atomiswave reuse the arcade glyph (user choice 2026-10-22: the set has none and the coloured themes clash), pico8, samcoupe, coco, dragon32, sordm5, trs80 have none → gamepad glyph).
- ROMs are read under `/userdata/roms` and, while the games card is mounted (`/run/nuubos/storage/sd2.status` `SD2_PATH`), under its `roms` folder in any case (else its root, ArkOS layout); its games are catalogued `sd2:<path>` (`:` never occurs on exFAT USERDATA), the game line field 9 is 2 for them (Home: "Insert the SD2 card with this game"), `DETAILS` adds `file=`/`root=` (scraper: one Skyscraper `-i` per card). ROMs are found loose or in any sub-folder (depth 6). System = nearest folder matching a system id/folder/name/alias (case/punctuation-insensitive, e.g. `Super Famicom`, `PS1`, `Genesis`) if it takes the extension, else the only system taking the extension, else header sniff (`.cue`/`.m3u` → PLAYSTATION / SEGASATURN / SEGADISCSYSTEM / SEGAKATANA; `.bin` with `SEGA` at 0x100 → Mega Drive). Still ambiguous (`.zip`, `.chd`, `.7z` loose) → skipped and counted in the log; needs a system folder. A game in a folder of its own, `<Folder>/EBOOT.PBP` (PSP homebrew and PSN games, GitHub #30), is named after the folder: title, identity (`game_id_for`: folder/EBOOT.PBP + size), cover and metadata names, and `name=` in DETAILS (the scraper's stem); an EBOOT.PBP right in a system's folder keeps "EBOOT" (`rom_name`/`rom_stem`; host test `eboot-folders.py`). Delete Game removes such a game's whole folder (`folder=1` in DETAILS; emulation.md "PSP games in a folder"). Their ids changed with this rule: the old "EBOOT" entries leave the catalog at the next scan. A file inside a system folder that this system does not take belongs to no system (GitHub #31, 2026-10-29: the `.col` stage files of a PSP port in `roms/psp` were listed as ColecoVision games); entries of such files from an older scan are dropped from the catalog at the next scan (`outside_its_folder`), not kept unavailable (their Delete would remove the port's file). Trade-off accepted: a ROM in another system's folder (a `.gb` in `roms/gba`) is no longer found by its extension. Host test `scan-folders.py` (also builds the libraryd of cf05a5c, before the fix, to make an old catalog). `.7z` (user report 2026-10-21, "most of my ROMs are 7zipped"): listed next to `zip` for every system whose ROMs RetroArch itself unpacks (RetroArch is built with HAVE_7ZIP; `cache_directory` is set by emud; cores never see the archive), not for MAME/mame2003 sets, DOS (dosbox-pure reads zip only), Geolith and the MAME-only machines started through a `.cmd`; the arcade systems already had it. libraryd creates `/userdata/roms/<folder>` per system. `.m3u`/`.cue` hide the files they reference; `media`, `covers`, `bios`… folders and dot-files are skipped.
- Shared catalog `/userdata/library/catalog.tsv` (v2: paths relative to roms/, identity = FNV-1a 64 of system + file name + size, so moving a ROM keeps history; same name+size twice = one game; older catalogs are rebuilt). Scans never delete: missing content becomes `available=0`. ROMs, BIOS and cover art are shared; history/favorites/collections are per user in `/userdata/users/<id>/library/{history.tsv,favorites.txt,collections.tsv}`.
- Add to Library (user request 2026-10-14: "import from the UI must take folders and playlists too, see PS1"): Files → Actions (marks or the focused file/folder, any location: USB, network location, internal storage) → "Add to Library" (1275). `nuubos-library-import` (nuubos-library, C) owns the placement, the same rules as the web's Add Games (connectivity.md): `plan SRC` prints `files= bytes= skipped= asks=`, `place<TAB>system<TAB>n`, `ask<TAB>n<TAB>label<TAB>files<TAB>ids` and `cand<TAB>n<TAB>id<TAB>name`; Home asks each ask with the choice sheet ("Which system is {0}?" 1276, label "<first file> (+N)", candidates by name; Back cancels the whole import before anything is copied), then runs job `library-import` (`run SRC n=system,...`, one job per selected item, progress in the Files status bar 1277) which copies to libraryd's `games_root/<system folder>/<path below SRC's parent>` (SD2 games card when mounted rw), never overwrites (an existing file = already there), `.part` + rename, space check (+16 MiB), then asks libraryd to SCAN (the reply is read, or libraryd drops the request) and reports `@result copied there skipped` (notice 1278 / 1279 / 1280). Files no system takes are skipped (readme.txt, .DS_Store). The Files job loop is shared (`run_jobs` in filesui.rs, also Copy/Move). Host test `python3 package/nuubos/nuubos-library/tests/import.py` (PS1 .m3u+.chd, nested .m3u→.cue→.bin with header sniff, .m3u+.pbp, floppy .m3u, system folders by name/id, unnamed tracks, .gdi, single file, re-import, unanswered ask). Hardware (CubeXX, 2026-10-14): a PS1 2-disc .m3u → .cue → .bin set in a subfolder went to `/media/sd2/roms/psx/<folder>/` with no question, appeared as one game after the job's scan, a second import reported all 5 files already there; removed again with `nuubos-libraryctl delete … confirm` (the catalog never drops a missing game by itself, EPIC-012; delete leaves empty folders). The controller flow itself is to be checked on the device (ui-shot scenes `files_actions`, `files_import_ask`, `files_importing`).
- Play history across consoles (Syncthing Play Activity, 2026-10-12): `history.tsv` is this console's own record (`id last time sessions off_time off_sessions reset`; old 4-field lines still read) and every save also writes it to `library/consoles/<console-id>.tsv` (console id = `/state/config/console-id`, random, created once; written at user load too when missing). The other files there (no dot files, no `.sync-conflict`, not our own) are added up: time/sessions summed, last = latest, inotify on that folder reloads them (Syncthing renames finished files in). Views (snapshot, Recently Played, DETAILS sessions, unplayed filter, previews) use the combined values (`hist_last/time/sessions`). STATS_RESET writes the other consoles' totals as negative offsets + the reset time into the own record, so the reset holds on every console (two independent resets of the same game can undercount; clamped at 0). Never one file written by two consoles. Host test `python3 package/nuubos/nuubos-library/tests/history-sync.py`; hardware-checked on the CubeXX (a dropped-in console file moved its game to the top of Recently Played with the summed time).
- Covers (shared, until EPIC-015 scraping writes the same store): `/userdata/library/covers/<system id>/<rom name>.png|jpg`, else `media/covers/<rom name>` next to the ROM. The UI decodes them on 3 worker threads (`COVER_DECODERS`; one before 2026-10-20), downscales to the card height in physical px with rounded corners (`library.rs` `shape_cover`), keeps an LRU of 64 and loads grid covers only for rows near the focus; a queued grid cover that leaves that window is dropped before decoding (`COVER_WANTED`, `cancel_cover`), so fast scrolling does not build a decode backlog. The grid instantiates a `HomeCardView` only for rows within `library-visible-rows + 1` of the focus row (the `for` creates a cheap empty cell per game): before 2026-10-09 every game of a system had a card whose GPU layer was blended every frame even when clipped out and kept until destroyed (GBA 269 cards: slow, GPU memory pressure, crashes on HDMI). Card width = height x real cover aspect (clamped 0.5–1.8), else the system aspect.
- Cover pack (user report 2026-10-20: covers slow to load with many games): scraped covers are ~0.5-1 MB PNGs at 720 rows, and decoding one was most of a card's cost. `load_cover_scaled` keeps each cover scaled to the decode height in `/userdata/library/cache/home-covers.pack` (one file because USERDATA is exFAT with 128 KB clusters: a first version with a file per cover took 128 KB each, 23 MB for 186 covers; the pack 4.8 MB, ~26 KB a cover). Records `key u64 LE | len u32 LE | JPEG q90 (opaque) or PNG`, key = std `DefaultHasher` of (path, size, mtime s+ns, height): a re-scraped cover gets a new record. Index read once by the first decoder (a torn tail is truncated); appends with `pwrite` under a mutex; past 192 MB the pack starts over (stale records are never removed otherwise). Measured on the CubeXX (tools: `uinput-nav`, UI restarted, open the SNES grid of 201 games and scroll 15 rows, CPU of Home's non-main threads): before 2.8 s, first visit 3.7 s (scaling + encoding, once), afterwards 1.1 s. Not in the console backup (cache).
