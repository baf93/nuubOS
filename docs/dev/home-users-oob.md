# General/Users, OOB, Home and Game Library

## General / users (§14)
Settings → General has User and Device areas; no space wasted on a generic category description. User: username/profile info, profile picture (default licensed avatar collection + user pictures from a per-user location), manage other users, create, delete with confirmation, startup user-selection behavior, default boot user. Device: date/time, timezone, automatic time sync, keyboard layout, startup behavior, Manage Users. Switch User performs a REAL user/session switch. The User Picker follows nuubOS grammar (top bar + bottom hint bar). With ≥2 users, product settings choose between the picker at boot and a configured default user.
- Built-in avatars (gaming style, 2026-10-07 user request): 24 DiceBear 10.x PNGs 256 px on retro-palette square backgrounds (01-08 Pixel Art, 09-16 Voxel Art, 17-24 Voxel Bot, all CC0 1.0; code MIT) regenerated by `tools/avatars/generate.sh`; attribution in `nuubos-users/src/avatars/README.txt` + `LICENSE-DiceBear.txt`. The UI shows every avatar as a rounded square.

## OOB / first boot (§15, EPIC-002)
Flow confirmed 2026-10-05, changed 2026-10-07 on explicit user request (Language step replaces Welcome): Language → Date & Time (timezone, automatic time, manual date/time) → Wi-Fi (skippable) → Users (≥1 user: name + avatar; Startup/Boot User when >1) → Ready → Home (or the user picker when the login mode requires it). Minimal, controller-first, nuubOS grammar. Same Product Services/contracts as Settings (no OOB-only logic/config stack); Date & Time reuses General timezone/automatic-time. Shown only while setup is incomplete; completion persists setup-complete. Implemented 2026-10-05.

- State owner: `nuubos-usersd`. `SETUP_COMPLETE=0|1` in `/state/config/nuubos.conf`; STATUS/SUBSCRIBE snapshots carry `setup_complete=`; `selection_required` is 0 while setup is pending. `COMPLETE_SETUP` (≥1 user, else `ERR no users`) fixes DEFAULT_USER if invalid, activates the default user when there is one user or login mode DEFAULT (before committing the flag, so a failed activation stays resumable), then writes the flag. `nuubos-usersctl complete-setup` does the same.
- S03: config v6. New configs get `SETUP_COMPLETE=0`; v1–v5 migrate to v6 with `SETUP_COMPLETE=1` only if a user profile exists (dev cards provisioned by `scripts/provision-state.sh` without users still get the OOB). While pending, S03 creates no "Player 1" and publishes no active user. A missing key in usersd counts as complete.
- UI (nuubui-home): `apply_users()` enters/leaves the OOB from the usersd snapshot (`enter_oob`/`leave_oob`, static `OOB_ACTIVE` routes input to `handle_oob_action`, Start is ignored, ui-context `oob` hides QM Switch User, inputd settings capture on). Steps: 0 Language and 4 Ready full-screen (`oob-hero`); 1 Date & Time = settings-view 30, 2 Wi-Fi = 31 (+ reused 2/4/6), 3 Users = 32 (+ reused 26 user detail, keyboard purpose 9). The Settings rail shows the steps. Wi-Fi step: when a connection is established while on the reused list (2) or network page (4), `apply_wifi_product_state` returns to step 31 with Continue focused (2026-10-07, user request: no detour through the network page after connecting); a failure keeps the user on the page with the error. Date & Time rows share `date_time_row_action()` with General rows 6–9. Every step commits immediately through the owning service, so an interrupted OOB restarts at Welcome with committed values kept.
- Language step (step 0, full-screen `oob-hero`): "Welcome" endonyms (not translated, order = `UI_LANGUAGES` in main.rs) roll on a drum (Slint `Timer` 2.6 s, running only on step 0; `greet-tick` animated 700 ms, scale-y fakes the rotation) above a `‹ Language ›` selector: left/right (or up/down) → `SET LANGUAGE` to localizationd, A → Date & Time. Language stays a per-user preference: with no active user localizationd writes `/state/users/default/localization.conf` (= device language), and a user without an own `localization.conf` gets the device language (else en), so the first user inherits the OOB choice.
- Creating a user (OOB or Settings → Manage Users) opens the avatar picker on the new user. The name keyboard (purposes 8/9, empty field) starts with Shift on (one-shot) so names begin capitalized.
- Test on target without reflashing: `sed -i 's/^SETUP_COMPLETE=.*/SETUP_COMPLETE=0/' /state/config/nuubos.conf` then `reboot` (existing users stay and are listed in the Users step). Headless: `tools/ui-shot/run.sh` renders `oob_*` scenes.

## Home (§16)
Close to the visual reference with native adaptive layouts: top status bar, hero, Recently Played, game metadata, Systems & Collections, Applications, controller hint bar. Home Music: MP3s from the active user's `music` dir, shuffled, own persistent volume; Quick Menu shows Skip while it plays; no audio routing/mixing logic in Home (audio.md).

## Home and Game Library (§37.11, EPIC-001/011/012/020)
- Owner `nuubos-libraryd` (package `nuubos-library`, `S47nuubos-library`, socket `/run/nuubos/libraryd.sock`, log `/run/nuubos/libraryd.log`, CLI `nuubos-libraryctl`). Same text protocol as usersd: `STATUS`/`SUBSCRIBE` snapshot ending in `end=1` (`recent=`, `collection=`, `system=`, `app=` lines), `GAMES\t<scope>` (`system:<id>`, `favorites`, `collection:<id>`, `recent`), `SESSION_BEGIN/END\t<game>` (Last Played/Time Played, sessions capped at 12 h), `SESSION_RECORD\t<game>\t<s>`, `FAVORITE\t<game>\t0|1`, `COLLECTION_CREATE/RENAME/DELETE/ADD/REMOVE`, `SCAN` (a request during a scan queues one more; snapshot `scanning=`, `games=` available, `scan_new=` games added or available again since the last `SCAN` received while idle, accumulated over a queued rescan; Settings → Gaming → Scan for New Games). Idle = 0 wakeups (poll without timeout, scan on a thread, active user via inotify on `/run/nuubos/user`).
- System registry (single source): `/usr/share/nuubos/systems.conf` (`id|name|folder|exts|cover aspect x1000|colour|folder aliases`), icons `/usr/share/nuubos/systems/<id>.png` (libretro retroarch-assets XMB Monochrome, CC BY 4.0, attribution in `nuubos-library/src/systems/ATTRIBUTION.txt`; pico8 has none → gamepad glyph).
- ROMs are read ONLY under `/userdata/roms`, loose or in any sub-folder (depth 6). System = nearest folder matching a system id/folder/name/alias (case/punctuation-insensitive, e.g. `Super Famicom`, `PS1`, `Genesis`) if it takes the extension, else the only system taking the extension, else header sniff (`.cue`/`.m3u` → PLAYSTATION / SEGASATURN / SEGADISCSYSTEM / SEGAKATANA; `.bin` with `SEGA` at 0x100 → Mega Drive). Still ambiguous (`.zip`, `.chd`, `.7z` loose) → skipped and counted in the log; needs a system folder. libraryd creates `/userdata/roms/<folder>` per system. `.m3u`/`.cue` hide the files they reference; `media`, `covers`, `bios`… folders and dot-files are skipped.
- Shared catalog `/userdata/library/catalog.tsv` (v2: paths relative to roms/, identity = FNV-1a 64 of system + file name + size, so moving a ROM keeps history; same name+size twice = one game; older catalogs are rebuilt). Scans never delete: missing content becomes `available=0`. ROMs, BIOS and cover art are shared; history/favorites/collections are per user in `/userdata/users/<id>/library/{history.tsv,favorites.txt,collections.tsv}`.
- Covers (shared, until EPIC-015 scraping writes the same store): `/userdata/library/covers/<system id>/<rom name>.png|jpg`, else `media/covers/<rom name>` next to the ROM. The UI decodes them on a worker thread, downscales to the card height in physical px with rounded corners (`library.rs` `shape_cover`), keeps an LRU of 64 and loads grid covers only for rows near the focus; a queued grid cover that leaves that window is dropped before decoding (`COVER_WANTED`, `cancel_cover`), so fast scrolling does not build a decode backlog. The grid instantiates a `HomeCardView` only for rows within `library-visible-rows + 1` of the focus row (the `for` creates a cheap empty cell per game): before 2026-10-09 every game of a system had a card whose GPU layer was blended every frame even when clipped out and kept until destroyed (GBA 269 cards: slow, GPU memory pressure, crashes on HDMI). Card width = height x real cover aspect (clamped 0.5–1.8), else the system aspect.
- Applications: `*.app` manifests (`ID=`, `NAME=`, `ICON=`, `ORDER=`) in `/usr/share/nuubos/applications` and `/userdata/applications`.
- Empty sections never disappear (user request 2026-10-08): an empty row shows a focusable `HomeEmptyCard` (icon + playful headline + one supporting line, i18n 714–726; Systems keeps the practical "copy your games" line, or "Searching for games…" while scanning) full row width, and no focus info; an empty Recently Played fills the covers + info band. `home-empty-variant` (Rust `pick_empty_variant`, per user session) picks the message. Up/down reach empty rows; a user's Home always starts on Recently Played, even when it is empty (user request 2026-10-08). ui-shot scenes `home` (all empty) and `home_unplayed`. A on a game launches it through nuubos-emud (§37.13); launching applications is NOT implemented yet (localized "Launching is not available yet" notice) — it needs a future app session service, which must call `SESSION_BEGIN/END`.
- `RESOLVE\t<game>` (libraryd) returns `OK <system>\t<absolute content path>` for an available game (used by emud).
- UI: `package/nuubos/nuubui-home/src/src/library.rs` (models, navigation, cover loader) + `HomeCard`/`HomeCardView`/`HomeTileView`/`HomeSectionTitle`/`HomeInfoPanel`/`HomeFocusRing`/`HomeRow` and the `home-view`/`library-grid` blocks in home.slint. Rows: 0 Recently Played (10 most recent, per user), 1 Systems & Collections (Favorites when non-empty, custom collections, systems with ≥1 available game), 2 Applications. Layout (reworked 2026-10-09, user request: bigger content, more spacing, readable text, the info bar no longer "thrown in"; replaces the 2026-10-08 one-screen layout): the Home scrolls vertically (`home-column`, `home-v-scroll`): row 0 at the top, rows 1/2 scroll to their section but never past `home-max-scroll`, so with a shelf selected the column ends exactly at the bottom (no empty space under Applications; the dimmed info panel of the covers stays visible above). Covers `home-big-h` ≈ 52 % of the rows height; under them `HomeInfoPanel` (title 24 px × s, chips like Game Details: system in its colour (`HomeCard.accent`), last played, time played (`HomeCard.last-played`/`play-time`, built in `game_card`), Unavailable warning; a notice replaces the chips); shelves are `HomeTileView` tiles (icon in a tonal well, systems tinted with their colour; name 18 px, count 14 px × s; `home-chip-h` fills the screen with the info panel, 64–96 px × s; `home-chip-w` 200–300 px × s, ~2.3 per row). Section titles 19 px × s, inactive ones in `text-secondary`. Edge fades under the bars while the column continues above/below. System/collection page (`library-grid`, user request "more nuubOS"): header with a wash of the system colour, the icon in its tinted well, name (24 px) + count, the platform silhouette as a faint watermark (`library-card` = the tile it was opened from), covers up to 82 % of the grid height, the same `HomeInfoPanel` under them. Notices of a tile row (e.g. "Launching is not available yet") appear in amber right of its title. A on a system/collection opens the grid, B closes it, `face_north` toggles Favorite. Home keeps the inputd UI capture (`set_ui_capture`, inputd "SETTINGS OPEN") whenever nuubUI is foreground; release it when a game/app takes over.
- inputd: new logical action `face_north` (default BTN_NORTH 307, remappable through the controllersd `face_north` control), routed like the navigation actions.
- Demo data on the dev target only (NOT in the repo; copyrighted box art for preview): placeholder ROM files named after real games in `/userdata/roms` (some loose, `My Collection/Super Famicom`, `Genesis`, multi-disc FF7), box art from libretro-thumbnails in `/userdata/library/covers/<id>/`, fake app manifests + Flathub icons in `/userdata/applications/` (`demo.*`). Remove (fish-safe): `ssh root@192.168.5.36 '/etc/init.d/S47nuubos-library stop; rm -rf /userdata/library/covers /userdata/applications/*.app /userdata/applications/icons /userdata/library/catalog.tsv /userdata/users/*/library/*; find /userdata/roms -type f -delete; /etc/init.d/S47nuubos-library start'`.
- Headless: `tools/ui-shot/run.sh` renders `home_*` scenes (recent/shelf/apps/grid/notice).
