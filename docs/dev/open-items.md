- Screensaver repaints ~12 fps; display state is not event-driven (forks `displayctl`); test-tone end uses a fixed sleep; listener reconnects use fixed 250/500 ms retries.

- Automatic time on network-up: done 2026-10-10 through the wpa_cli CONNECTED event + boot (system.md "Online sync"), in nuubos-status rather than regionald. - Emulation (2026-10-06, §37.13) needs hardware qualification of the whole flow with real input (launch from Home, play, Quick Menu GAME actions, hotkeys, sleep/wake and power off during a game, HDMI); rumble does not reach games yet (the game gamepads have no EV_FF; forwarding to the pwm-vibrator/rumbled is still to do); direct scan-out of RetroArch not yet verified (`/sys/kernel/debug/dri/0/state` showed XR24 640x480); Home keeps its window under RetroArch and may block in eglSwapBuffers while occluded if it redraws (self-heals when visible again; measure); the RAW stream inputd sends to controllersd/systemd for activity is per event even while gaming (rate-limit candidate).
- PC streaming (2026-10-06, §37.14): the decode/presentation path is qualified on RG40XX-V with test clips; still needs a real Sunshine/GameStream host for pairing, app list, stream start/quit (+ close app), Quick Menu STREAM rows/statistics, controller input, audio/AV sync, Wi-Fi latency, sleep/power off during a stream and HDMI. Not done: rumble to the host (same EV_FF gap as games), host Wake-on-LAN, HDR (Cedrus is 8-bit only).
- Steam Link (2026-10-06, §37.15): the Valve app, the Qt Wayland plugin and the gamepads were checked on RG40XX-V by hand (prototype); the integrated flow (download from the page, launch, pairing and a real stream from a Steam PC, Cedrus decode actually used by Steam Link — `/run/nuubos/steamlink.log` should say "hardware decoding", QM over it, sleep/power off during a session, HDMI, update/remove) still needs hardware qualification. In the prototype Steam Link exited by itself once while Home started a game underneath (input routing then went to Home): re-check with the integrated session.
- controllersd/rumbled/lightingd store preferences under the pseudo-user `/state/users/default` while no user is active (user picker, OOB); those values never migrate to the user created afterwards.
