- Rumble driver slept in atomic context (found 2026-10-29, CubeXX, during the throttle A/B): `rg35xx_pro_play_effect()` (kernel `patches/linux/device/rg35xx-pro/0001`, the "pwm-vibrator" motor) took `h->lock` (a mutex) in the force-feedback play callback, which the input core calls under the device's event spinlock with interrupts off: "BUG: scheduling while atomic: nuubos-inputd" + "Voluntary context switch within RCU read-side critical section" when the rumble work held the mutex (inputd forwarding a game's rumble through evdev). Fixed: the callback only stores the level (`WRITE_ONCE`) and schedules the work, which applies it under the mutex. Kernel #17 on the CubeXX: 5 rumbles through evdev + Mario Kart DS/64, 0 kernel warnings. Previous kernel in `/userdata/Image.pre-ff`.
